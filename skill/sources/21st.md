# 21st.dev

21st.dev is a marketplace of React components made by the community. Motif uses it for component ideas and, on React web, for code to adapt; a free key allows unlimited search and two code copies a day.

## Is it connected?

Look for tools named `search`, `get_component`, `get_inspiration` and `search_logo` that come from a server whose name includes "21st". Your agent may show them with a prefix of its own. The tool names alone are too generic to trust: other servers have tools called `search` too, so check where they come from.

Tools whose names start with `21st_magic_` come from the retired Magic server. Treat that as not connected: suggest removing the old server from the agent's settings and running `motif connect 21st`.

## When it's connected

- **Search first.** Call `search` (free and unlimited) for a component the guide doesn't have yet ("pricing table", "date range picker"). Show the developer two or three candidates and pick one together.
- **Ideas.** Call `get_inspiration` for visual ideas when the developer wants options before choosing.
- **Logos.** Call `search_logo` only for a company logo the developer asked for.
- **Fetch code only for the chosen component.** Call `get_component` once, for the one component actually chosen: the free key allows two copies a day.

**React web: adapt the code.**

1. Every colour, size, radius, shadow, font and timing becomes a role from the guide.
2. Drop dependencies the project doesn't need, and use the project's own primitives where they exist.
3. Keep a licence notice if the author's licence asks for one.
4. Add the component to the guide's Components section, with its variants and states.
5. Run `motif check` and fix what it finds until it reports nothing.

**Other stacks: treat it as a picture.** Read the component for its structure and behaviour, then rebuild it natively from the adapter's guidance. Don't translate React code line by line.

## When it isn't

- Build from the adapter's component guidance, [visual craft](../knowledge/visual-craft.md) and the UX pattern guides.
- When the developer points to a public component page on 21st.dev, you may read that page for ideas.
- Don't collect pages in bulk: the terms forbid it.

## Connecting

`motif connect 21st` asks for the free key in the developer's own terminal, with hidden input, and sets it up for Claude Code. Never ask the developer to paste a key into the chat. On a computer without Claude Code it prints the settings to paste into another agent instead; the server address is `https://21st.dev/api/mcp` and the key goes in the `x-api-key` header.

## Rules

- Restyle everything into the guide's roles; `motif check` must pass.
- One component at a time, chosen with the developer.
- Respect each component's licence.
- If a call fails or the daily limit is reached, build the component from the guidance and say so once.
