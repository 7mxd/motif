# Theme code

What `motif tokens` writes for an Angular app, how to wire it in once, and how components use the theme values.

## What motif tokens writes

| File | Holds |
|---|---|
| `motif.css` | A CSS variable per role: `--motif-color-action-primary`, `--motif-space-4`, `--motif-font-body-size` and so on. Light values sit on `:root`; dark values apply under `prefers-color-scheme: dark` and on `[data-theme="dark"]`; `[data-theme="light"]` forces light. When the design guide has variants, each also gets `:root[data-variant="<id>"]` blocks. It also stops CSS animations and transitions when reduced motion is on. |
| `motif.tailwind.css` | Tailwind v4 projects only. It imports `motif.css` and maps Tailwind's utilities to the roles, and removes Tailwind's default colours, radii, shadows, text sizes, fonts and easings. |
| `motion.ts` | `duration` (in seconds), `easing` (cubic Bézier arrays) and `spring` (Motion's `{ type: "spring", visualDuration, bounce }`), for Motion's `animate()`. |

They go in `src/styles/` (`motif.css`, `motif.tailwind.css`, beside the global `src/styles.css`) and `src/app/design/motion.ts`; when `angular.json` names another `sourceRoot`, they follow it. `themeDir` in `design/motif.json` wins. The files are the same as a React web app's for the same guide. Every generated file starts with a "Generated by Motif" line. Never edit them: change `design/tokens.json`, then run `motif tokens` again.

Import `motion.ts` with a path relative to the component: `../design/motion` from `src/app/<component>/`.

## Wiring it in once

**A fresh starter.** `ng new`'s `src/styles.css` is empty apart from a comment (and Tailwind's import with `--style=tailwind`), but the starter's `app.html` is a large demo page with its own colours, fonts and sizes in a `<style>` block. Replace all of it when you write the first page.

**Plain CSS.** Import `motif.css` once, at the top of `src/styles.css`:

```css
@import "./styles/motif.css";
```

**Sass.** At the top of `src/styles.scss`: `@use "./styles/motif.css";`.

**Tailwind v4.** In `src/styles.css`, import `motif.tailwind.css` right after `@import "tailwindcss";`:

```css
@import "tailwindcss";
@import "./styles/motif.tailwind.css";
```

Importing it before Tailwind would let Tailwind's defaults win. Motif never edits `angular.json`: its `styles` array already lists `src/styles.css`, so the import above is all it takes. `motif tokens` reminds you when this wiring is missing.

## Using the values

| Role | Tailwind | CSS |
|---|---|---|
| `color.background` | `bg-background` | `var(--motif-color-background)` |
| `color.text-primary` | `text-text-primary` | `var(--motif-color-text-primary)` |
| `color.action-primary` with `color.on-action-primary` | `bg-action-primary text-on-action-primary` | `var(--motif-color-action-primary)` |
| `color.border` | `border-border` | `var(--motif-color-border)` |
| `space.4` | `p-4`, `gap-4`, `mt-4` | `var(--motif-space-4)` |
| `radius.md` | `rounded-md` | `var(--motif-radius-md)` |
| `shadow.md` | `shadow-md` | `var(--motif-shadow-md)` |
| `font.body` | `font-body text-body` | `var(--motif-font-body-family)` and `var(--motif-font-body-size)` |
| `easing.standard` | `ease-standard` | `var(--motif-easing-standard)` |
| `duration.base` with `easing.standard` | `transition` | `var(--motif-duration-base)` |

In a component's styles (its `.css` file or `styles:`), use the CSS variables: Angular scopes them to the component, and the variables still reach it. In a template, use the classes (Tailwind) or a class of the component's own. For one dynamic value, bind a variable: `[style.color]="'var(--motif-color-text-primary)'"`. Take motion values from the generated `motion.ts` ([motion](motion.md)).

## Dark mode

Dark mode follows the system automatically. To offer a switch, set `data-theme="dark"` or `data-theme="light"` on `<html>` and remember the choice; remove the attribute to follow the system again. Never use Tailwind's `dark:` variant for colours: the roles already change on their own.

## Switching variants

When the design guide has variants, choose one by setting `data-variant="<id>"` on `<html>`, the same element as `data-theme`. The default variant needs no attribute. Tailwind classes and `var(--motif-…)` follow on their own; write no per-variant classes.

From the app's state, set `document.documentElement.dataset.variant`. Keep the choice in a signal in a service, and set the attribute through Angular's `DOCUMENT` (from `@angular/core`; before Angular 20, from `@angular/common`) rather than the global `document`. With server rendering (`--ssr`), the server renders the page into its own `DOCUMENT`, so the service sets the attribute there too and the page starts in the right variant instead of flashing the default. Remember the choice in a cookie, which the server can read (`REQUEST`, Angular 19 and later), rather than `localStorage`, which only the browser can:

```ts
import { DOCUMENT, Injectable, REQUEST, inject, signal } from '@angular/core';

const VARIANT = /^[a-z0-9-]+$/;

@Injectable({ providedIn: 'root' })
export class VariantService {
  private readonly document = inject(DOCUMENT);
  private readonly request = inject(REQUEST, { optional: true });
  readonly variant = signal<string | null>(this.saved());

  constructor() {
    this.apply(this.variant());
  }

  choose(variant: string | null): void {
    this.variant.set(variant);
    this.apply(variant);
    this.document.cookie = variant
      ? `variant=${variant}; path=/; max-age=31536000; samesite=lax`
      : 'variant=; path=/; max-age=0';
  }

  private apply(variant: string | null): void {
    const html = this.document.documentElement;
    if (variant) html.setAttribute('data-variant', variant);
    else html.removeAttribute('data-variant');
  }

  /** The saved variant, from the request's cookies on the server and the page's in the browser. A cookie is the visitor's text, so check it. */
  private saved(): string | null {
    const cookies = this.request?.headers.get('cookie') ?? this.document.cookie ?? '';
    const value = /(?:^|;\s*)variant=([^;]*)/.exec(cookies)?.[1] ?? '';
    return VARIANT.test(value) ? value : null;
  }
}
```

Create the service when the app starts, in `src/app/app.config.ts`, so it sets the attribute before the first render on the server and in the browser (`provideAppInitializer` is Angular 19 and later; before that, an `APP_INITIALIZER` provider); a settings screen calls `choose()`:

```ts
import { ApplicationConfig, inject, provideAppInitializer } from '@angular/core';
import { provideRouter } from '@angular/router';
import { routes } from './app.routes';
import { VariantService } from './variant.service';

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes),
    provideAppInitializer(() => {
      inject(VariantService);
    }),
  ],
};
```

`setAttribute` works on the server's document as on the browser's. A prerendered page has no request, and `ng new --ssr` prerenders every route by default (`renderMode: RenderMode.Prerender` in `src/app/app.routes.server.ts`): such a page shows the default variant until the browser applies the saved one. Render the routes whose first paint depends on the variant on the server for each request instead:

```ts
import { RenderMode, ServerRoute } from '@angular/ssr';

export const serverRoutes: ServerRoute[] = [
  { path: '**', renderMode: RenderMode.Server },
];
```

(Name the routes, rather than `**`, to keep prerendering the rest.) Set both attributes on `<html>`: the variant selectors are scoped to `:root`.

## Fonts

`motif tokens --json` lists the theme's `fonts`: each family with the weights its roles use. Load each one with its Fontsource package, and import each weight once:

```bash
npm install @fontsource/onest
```

In `src/styles.css`, right after the Motif import of [the wiring above](#wiring-it-in-once) (`motif.css`, or with Tailwind `motif.tailwind.css`, which already imports it; don't add the other):

```css
@import "@fontsource/onest/400.css";
@import "@fontsource/onest/600.css";
```

The package name is the family in lower case with hyphens (`@fontsource/source-serif-4`). An Arabic companion, second in the font list, loads the same way. Don't use `@fontsource-variable` for theme fonts: it registers the family under another name, so the theme's names wouldn't match.

A font with no Fontsource package is served with the app: files and licence in `src/assets/fonts/`, declared once in `src/styles.css` with `@font-face` under the exact family name the theme uses, and a `url()` relative to `styles.css` (`url('./assets/fonts/onest.woff2')`), which the build bundles.

## Angular Material

Angular Material 3 colours its components with `--mat-sys-*` variables. To make Material follow the design guide, map them to Motif's in `src/styles.css` (or `styles.scss`), after Material's theme (`@include mat.theme(…)`), so they win:

```css
html {
  --mat-sys-primary: var(--motif-color-action-primary);
  --mat-sys-on-primary: var(--motif-color-on-action-primary);
  --mat-sys-surface: var(--motif-color-surface);
  --mat-sys-on-surface: var(--motif-color-text-primary);
  --mat-sys-on-surface-variant: var(--motif-color-text-secondary);
  --mat-sys-outline-variant: var(--motif-color-border);
  --mat-sys-error: var(--motif-color-danger);
  --mat-sys-on-error: var(--motif-color-on-danger);
}
```

Motif's variables change with dark mode and variants, so Material's follow. Restyle what the mapping doesn't reach through the variables too, never with colours of your own. `motif extract` reads these variables when it drafts a guide from a Material app.

## Tailwind v3

Motif writes the CSS variables only. Use them as `bg-[var(--motif-color-action-primary)]`, or upgrade to Tailwind v4 for the generated theme.
