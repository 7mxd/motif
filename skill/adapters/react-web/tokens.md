# Theme code

What `motif tokens` writes for a React web app, how to wire it in once, and how components use the theme values.

## What motif tokens writes

| File | Holds |
|---|---|
| `src/styles/motif.css` | A CSS variable per role: `--motif-color-action-primary`, `--motif-space-4`, `--motif-font-body-size` and so on. Light values sit on `:root`; dark values apply under `prefers-color-scheme: dark` and on `[data-theme="dark"]`; `[data-theme="light"]` forces light. When the design guide has variants, each also gets `:root[data-variant="<id>"]` blocks for light, dark (the media query and `[data-theme="dark"]`). |
| `src/styles/motif.tailwind.css` | Tailwind v4 projects only. It imports `motif.css` and maps Tailwind's utilities to the roles. It also removes Tailwind's default colours, radii, shadows, text sizes, fonts and easings, so only the theme's exist. |
| `src/design/motion.ts` | `duration` (in seconds), `easing` (cubic Bézier arrays) and `spring` (Motion's `{ type: "spring", visualDuration, bounce }`). |

The source folder follows the project (`src/`, or `app/` when there's no `src/`), as recorded in `design/motif.json`. An app without TypeScript (a `jsconfig.json` and no `tsconfig.json`, or only `.js` files) gets `motion.js` instead, with the same exports and its types as JSDoc comments; wherever this guide says `motion.ts`, read `motion.js`.

Every generated file starts with a "Generated by Motif" line. Never edit them: change `design/tokens.json`, then run `motif tokens` again.

## Wiring it in, once

**A fresh starter.** Starters ship their own theme, which would override the design guide's, so remove it first:

- Next.js: in `src/app/globals.css`, delete the starter's `:root` variables, its `@theme inline` block, its `@media (prefers-color-scheme: dark)` block and its `body` rule, keeping only the imports. In `src/app/layout.tsx`, remove the Geist fonts: the `next/font/google` import, the `Geist(…)` calls and their class names on `<body>`.
- Vite: in `src/index.css`, delete everything except the imports, and empty `src/App.css` (or delete it and its import).

**Tailwind v4.** In the main CSS file (Next.js: `src/app/globals.css`; Vite: `src/index.css`), import `motif.tailwind.css` right after `@import "tailwindcss";`, with a path relative to that CSS file. In a Next.js project:

```css
@import "tailwindcss";
@import "../styles/motif.tailwind.css";
```

Importing it before Tailwind would let Tailwind's defaults win.

**Without Tailwind.** Import `motif.css` once, from the main CSS file or from the app's entry file.

`motif tokens` reminds you when this wiring is missing.

## Using the values

| Role | Tailwind | CSS |
|---|---|---|
| `color.background` | `bg-background` | `var(--motif-color-background)` |
| `color.text-primary` | `text-text-primary` | `var(--motif-color-text-primary)` |
| `color.action-primary` with `color.on-action-primary` | `bg-action-primary text-on-action-primary` | `var(--motif-color-action-primary)` |
| `color.border` | `border-border` | `var(--motif-color-border)` |
| `space.4` | `p-4`, `gap-4`, `mt-4` | `var(--motif-space-4)` |
| `radius.md` | `rounded-md` | `var(--motif-radius-md)` |
| `shadow.md` | `shadow-md` | `var(--motif-shadow-md)` |
| `font.body` | `font-body text-body` (the family, then the size with its line height and weight) | `var(--motif-font-body-family)` and `var(--motif-font-body-size)` |
| `color.brand` with `color.on-brand`, `color.brand-soft` (optional, for brand moments such as a hero band or an icon tile; never buttons or links) | `bg-brand text-on-brand`, `bg-brand-soft` (only when the theme has the roles) | `var(--motif-color-brand)` |
| `font.mono` (optional, for code) | `font-mono` (only when the theme has the role: Motif's theme replaces Tailwind's own font classes) | `var(--motif-font-mono-family)` |
| `easing.standard` | `ease-standard` | `var(--motif-easing-standard)` |
| `duration.base` with `easing.standard` | `transition` | — |

In TypeScript, import motion values from `@/design/motion`; everything else is a class or a CSS variable. `@/` is the import alias the Next.js starter sets up; in a project without one (the Vite starter), use a relative path such as `../design/motion`.

## Dark mode

Dark mode follows the system automatically. To offer a switch, set `data-theme="dark"` or `data-theme="light"` on `<html>` and remember the choice; remove the attribute to follow the system again.

Never use Tailwind's `dark:` variant for colours: the roles already change on their own.

## Variants

When the design guide has variants, choose one by setting `data-variant="<id>"` on `<html>`, the same element as `data-theme`, so they combine with each other and with the system's dark setting. The default variant needs no attribute. Tailwind classes follow on their own, since they read the same variables; write no per-variant classes.

```tsx
document.documentElement.dataset.variant = "men"; // remove it to return to the default
```

Set both on `<html>`. The variant selectors are scoped to `:root`, so an inner element with its own `data-theme` doesn't keep the variant. Remember the choice and apply it before the page is drawn, as for a saved theme (in Next.js, a small inline script in the layout's `<head>`), so no one sees the default first.

## Fonts

`motif tokens --json` lists the theme's `fonts`: each family with the weights its roles use (fonts every computer has are left out). Load each one with its Fontsource package:

```bash
npm install @fontsource/onest
```

The package name is the family in lower case with hyphens for spaces: Onest is `@fontsource/onest`, Source Serif 4 is `@fontsource/source-serif-4`. Then import each weight once, in the root (Next.js: `src/app/layout.tsx`; Vite: `src/main.tsx`):

```tsx
import "@fontsource/onest/400.css";
import "@fontsource/onest/600.css";
```

An Arabic companion, second in the theme's font list (such as Readex Pro), loads the same way: install its package and import the same weights. Its Arabic files download only when a page shows Arabic text.

The font files are served with the app, so nothing loads from Google when people use it.

Don't use `next/font` or the `@fontsource-variable` packages for theme fonts: both register the font under a different family name, so the theme's names wouldn't match and text would fall back.

A font with no Fontsource package (a brand font, or one the developer bought) is served with the app: put its files and licence in `public/fonts/`, and declare it once under the exact family name the theme uses, in a stylesheet the root imports (Next.js: `src/app/globals.css`; Vite: `src/index.css`). A project font named under `fonts` in the design guide is this case: `motif tokens` never downloads fonts, previews load the files from the project, and the app loads them itself with `@font-face`, using the family name from the guide. If the guide's paths point elsewhere (`assets/fonts/…`), serve that folder or move the files and update the guide.

A variable font covers every weight with one file, declared with its range:

```css
@font-face {
  font-family: "Acme Sans";
  src: url("/fonts/acme-sans.woff2") format("woff2");
  font-weight: 400 700;
  font-display: swap;
}
```

Static files (a Regular and a Bold) get one `@font-face` each, under the same family name, so bold text uses the bold file:

```css
@font-face {
  font-family: "Acme Sans";
  src: url("/fonts/acme-sans-regular.woff2") format("woff2");
  font-weight: 400;
  font-display: swap;
}
@font-face {
  font-family: "Acme Sans";
  src: url("/fonts/acme-sans-bold.woff2") format("woff2");
  font-weight: 700;
  font-display: swap;
}
```

## Tailwind v3

Motif writes the CSS variables only. Use them as `bg-[var(--motif-color-action-primary)]`, or upgrade to Tailwind v4 for the generated theme.
