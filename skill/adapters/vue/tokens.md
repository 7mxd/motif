# Theme code

What `motif tokens` writes for a Vue or Nuxt app, how to wire it in once, and how components use the theme values.

## What motif tokens writes

| File | Holds |
|---|---|
| `motif.css` | A CSS variable per role: `--motif-color-action-primary`, `--motif-space-4`, `--motif-font-body-size` and so on. Light values sit on `:root`; dark values apply under `prefers-color-scheme: dark` and on `[data-theme="dark"]`; `[data-theme="light"]` forces light. When the design guide has variants, each also gets `:root[data-variant="<id>"]` blocks. |
| `motif.tailwind.css` | Tailwind v4 projects only. It imports `motif.css` and maps Tailwind's utilities to the roles, and removes Tailwind's default colours, radii, shadows, text sizes, fonts and easings. |
| `motion.ts` | `duration` (in seconds), `easing` (cubic Bézier arrays) and `spring` (Motion's `{ type: "spring", visualDuration, bounce }`), for `motion-v`. Not written for Vue 2. |

Where they go:

| App | `motif.css`, `motif.tailwind.css` | `motion.ts` |
|---|---|---|
| Vite Vue | `src/styles/` | `src/design/motion.ts` |
| Nuxt | `<srcDir>/assets/css/` (`app/assets/css/` in Nuxt 4) | `<srcDir>/design/motion.ts` |
| Nuxt 3 at the project root | `assets/css/` | `motion/motif-motion.ts`, because the root's `design/` is Motif's own |

`themeDir` in `design/motif.json` wins over all of these. Every generated file starts with a "Generated by Motif" line. Never edit them: change `design/tokens.json`, then run `motif tokens` again.

## Wiring it in once

**A fresh starter.** Starters ship their own theme, which would override the design guide's, so remove it first:

- Vue's starter: `src/assets/base.css` has `:root` variables and a `@media (prefers-color-scheme: dark)` block, and `src/assets/main.css` styles `#app` and the links. Delete the colour variables, the dark block and the colours in `main.css`. If the starter's components read `--color-background`, `--color-text` and the like, a starter's `base.css` variables can map to Motif's instead of rewriting every component; replace them as you go:

```css
:root {
  --color-background: var(--motif-color-background);
  --color-text: var(--motif-color-text-primary);
  --color-border: var(--motif-color-border);
}
```

- Nuxt's starter has no stylesheet; delete `<NuxtWelcome />` when you add the first page.

**Vite, plain CSS.** Import `motif.css` once, first, in `src/main.ts`:

```ts
import './styles/motif.css'
import './assets/main.css'
```

**Nuxt, plain CSS.** List it first in `nuxt.config.ts`:

```ts
export default defineNuxtConfig({
  css: ['~/assets/css/motif.css'],
})
```

(In a Nuxt 3 app at the project root, `~/` is the project root, so the path is the same.)

**Tailwind v4.** In the main CSS file (Vite: `src/assets/main.css`; Nuxt: `assets/css/main.css`, listed in `css`), import `motif.tailwind.css` right after `@import "tailwindcss";`, with a path relative to that CSS file. In Vite:

```css
@import "tailwindcss";
@import "../styles/motif.tailwind.css";
```

Importing it before Tailwind would let Tailwind's defaults win. `motif tokens` reminds you when this wiring is missing.

## Using the values

| Role | Tailwind | CSS |
|---|---|---|
| `color.background` | `bg-background` | `var(--motif-color-background)` |
| `color.text-primary` | `text-text-primary` | `var(--motif-color-text-primary)` |
| `color.action-primary` with `color.on-action-primary` | `bg-action-primary text-on-action-primary` | `var(--motif-color-action-primary)` |
| `color.border` | `border-border` | `var(--motif-color-border)` |
| `space.4` | `p-4`, `gap-4`, `mt-4` | `var(--motif-space-4)` |
| `radius.md` | `rounded-md` | `var(--motif-radius-md)` |
| `shadow.md` | `shadow-md` | `var(--motif-shadow-md)` |
| `font.body` | `font-body text-body` | `var(--motif-font-body-family)` and `var(--motif-font-body-size)` |
| `easing.standard` | `ease-standard` | `var(--motif-easing-standard)` |
| `duration.base` with `easing.standard` | `transition` | `var(--motif-duration-base)` |

In a component's `<style scoped>`, use the CSS variables; in a template, use the classes (Tailwind) or a scoped class. In a `:style` binding, give a variable: `:style="{ color: 'var(--motif-color-text-primary)' }"`. Import motion values from the generated `motion.ts` (`~/design/motion` in Nuxt, or `~/motion/motif-motion` for a Nuxt 3 app at the project root; a relative path or your `@/` alias in Vite).

## Dark mode

Dark mode follows the system automatically. To offer a switch, set `data-theme="dark"` or `data-theme="light"` on `<html>` and remember the choice; remove the attribute to follow the system again. Never use Tailwind's `dark:` variant for colours: the roles already change on their own.

## Switching variants

When the design guide has variants, choose one by setting `data-variant="<id>"` on `<html>`, the same element as `data-theme`. The default variant needs no attribute. Tailwind classes and `var(--motif-…)` follow on their own; write no per-variant classes.

From the app's state, in Vue, set `document.documentElement.dataset.variant`:

```ts
import { ref, watchEffect } from 'vue'

const variant = ref<string | null>(null)
watchEffect(() => {
  if (variant.value) document.documentElement.dataset.variant = variant.value
  else delete document.documentElement.dataset.variant
})
```

That runs in the browser only. In Nuxt the server renders the page first, so set the attribute with `useHead` too, and a server-rendered page starts in the right variant instead of flashing the default:

```ts
const variant = useState<string | null>('variant', () => null)
useHead({ htmlAttrs: { 'data-variant': () => variant.value ?? undefined } })
```

Remember the choice in a cookie (`useCookie`), which the server can read, rather than `localStorage`, which only the browser can. In Vite, apply a saved variant in `src/main.ts` before `mount`, so no one sees the default first. Set both attributes on `<html>`: the variant selectors are scoped to `:root`.

## Fonts

`motif tokens --json` lists the theme's `fonts`: each family with the weights its roles use. Load each one with its Fontsource package, and import each weight once:

```bash
npm install @fontsource/onest
```

Vite: in `src/main.ts`, after the Motif import:

```ts
import '@fontsource/onest/400.css'
import '@fontsource/onest/600.css'
```

Nuxt: add `'@fontsource/onest/400.css'` to the `css` list in `nuxt.config.ts`, after `motif.css`. The package name is the family in lower case with hyphens (`@fontsource/source-serif-4`). An Arabic companion, second in the font list, loads the same way. Don't use `@fontsource-variable` or `@nuxt/fonts` for theme fonts: they register the family under another name, so the theme's names wouldn't match.

A font with no Fontsource package is served with the app: files and licence in `public/fonts/`, declared once with `@font-face` under the exact family name the theme uses, in a stylesheet the root imports.

## Tailwind v3

Motif writes the CSS variables only. Use them as `bg-[var(--motif-color-action-primary)]`, or upgrade to Tailwind v4 for the generated theme.
