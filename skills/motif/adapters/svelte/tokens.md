# Theme code

What `motif tokens` writes for a Svelte or SvelteKit app, how to wire it in once, and how components use the theme values.

## What motif tokens writes

| File | Holds |
|---|---|
| `motif.css` | A CSS variable per role: `--motif-color-action-primary`, `--motif-space-4`, `--motif-font-body-size` and so on. Light values sit on `:root`; dark values apply under `prefers-color-scheme: dark` and on `[data-theme="dark"]`; `[data-theme="light"]` forces light. When the design guide has variants, each also gets `:root[data-variant="<id>"]` blocks. |
| `motif.tailwind.css` | Tailwind v4 projects only. It imports `motif.css` and maps Tailwind's utilities to the roles, and removes Tailwind's default colours, radii, shadows, text sizes, fonts and easings. |
| `motion.ts` | `duration` (in milliseconds), `easing` (functions), `spring` (`{ stiffness, damping }` for Svelte's `Spring`) and `motionSpring` (Motion's `{ type: "spring", visualDuration, bounce }`). Not written for Svelte 4. |

They go in `src/lib/styles/` (`motif.css`, `motif.tailwind.css`) and `src/lib/design/motion.ts`. `themeDir` in `design/motif.json` wins. An app without TypeScript (a `jsconfig.json` and no `tsconfig.json`, or only `.js` files) gets `motion.js` instead, with the same exports and its types as JSDoc comments; wherever this guide says `motion.ts`, read `motion.js`. Every generated file starts with a "Generated by Motif" line. Never edit them: change `design/tokens.json`, then run `motif tokens` again.

The import path of `motion.ts` depends on the app. SvelteKit 2: `$lib/design/motion`. SvelteKit 3: `#lib/design/motion`, because `$lib` is gone, when `package.json` maps `#lib/*` in `imports` (sv's SvelteKit 3 starter does); without that map, a relative path. Plain Vite: a relative path (`./lib/design/motion` from `src/`). `motif check` names the right one in its fix.

## Wiring it in once

**A fresh starter.** Starters can ship their own theme, which would override the design guide's, so remove it first:

- SvelteKit's minimal starter has no stylesheet. Its demo template and the Tailwind add-on put styles in the file `src/routes/+layout.svelte` imports (`src/routes/layout.css` in recent `sv` versions, `src/app.css` before). Delete the colour variables and the colours in it; keep a Tailwind `@import "tailwindcss";`.
- Vite's starter has `src/app.css` with `:root` colours and a `prefers-color-scheme` block, and `src/lib/Counter.svelte` with a styled button. Delete the colours; delete `Counter.svelte` when you replace the demo page.

**SvelteKit, plain CSS.** Import `motif.css` once, first, in `src/routes/+layout.svelte`:

```svelte
<script lang="ts">
  import '$lib/styles/motif.css';
  import './layout.css';

  let { children } = $props();
</script>

{@render children()}
```

(In SvelteKit 3 the first import is `#lib/styles/motif.css`, or a relative path when `package.json` has no `#lib/*` map.)

**Vite, plain CSS.** Import it first in `src/main.ts` (or `main.js`):

```ts
import './lib/styles/motif.css'
import './app.css'
```

**Tailwind v4.** In the main CSS file, import `motif.tailwind.css` right after `@import "tailwindcss";`, with a path relative to that CSS file. In SvelteKit's `src/routes/layout.css`:

```css
@import "tailwindcss";
@import "../lib/styles/motif.tailwind.css";
```

Importing it before Tailwind would let Tailwind's defaults win. `motif tokens` reminds you when this wiring is missing.

## Using the values

| Role | Tailwind | CSS |
|---|---|---|
| `color.background` | `bg-background` | `var(--motif-color-background)` |
| `color.text-primary` | `text-text-primary` | `var(--motif-color-text-primary)` |
| `color.action-primary` with `color.on-action-primary` | `bg-action-primary text-on-action-primary` | `var(--motif-color-action-primary)` |
| `color.border` | `border-border` | `var(--motif-color-border)` |
| `space.4` | `p-4`, `gap-4`, `mt-4` | `var(--motif-space-4)` |
| `radius.md` | `rounded-md` | `var(--motif-radius-md)` |
| `shadow.md` | `shadow-md` | `var(--motif-shadow-md)` |
| `font.body` | `font-body text-body` | `var(--motif-font-body-family)` and `var(--motif-font-body-size)` |
| `easing.standard` | `ease-standard` | `var(--motif-easing-standard)` |
| `duration.base` with `easing.standard` | `transition` | `var(--motif-duration-base)` |

In a component's `<style>` (scoped by Svelte), use the CSS variables; in markup, use the classes (Tailwind). For one dynamic value use a `style:` directive with a variable: `style:color="var(--motif-color-text-primary)"`. Take motion values from the generated `motion.ts` ([motion](motion.md)).

## Dark mode

Dark mode follows the system automatically. To offer a switch, set `data-theme="dark"` or `data-theme="light"` on `<html>` and remember the choice; remove the attribute to follow the system again. Never use Tailwind's `dark:` variant for colours: the roles already change on their own.

## Switching variants

When the design guide has variants, choose one by setting `data-variant="<id>"` on `<html>`, the same element as `data-theme`. The default variant needs no attribute. Tailwind classes and `var(--motif-…)` follow on their own; write no per-variant classes.

From the app's state, set `document.documentElement.dataset.variant`. Keep the state in a module with runes (`src/lib/variant.svelte.ts`) and apply it from an effect in the root layout, which also remembers the choice in a cookie (the server can't read `localStorage`):

```ts
export const theme = $state<{ variant: string | null }>({ variant: null })
```

```svelte
<script lang="ts">
  import { theme } from '$lib/variant.svelte';

  let { children } = $props();

  $effect(() => {
    if (theme.variant) {
      document.documentElement.dataset.variant = theme.variant;
      document.cookie = `variant=${theme.variant}; path=/; max-age=31536000; samesite=lax`;
    } else {
      delete document.documentElement.dataset.variant;
      document.cookie = 'variant=; path=/; max-age=0';
    }
  });
</script>

{@render children()}
```

An effect runs in the browser only. In SvelteKit the server renders the page first, so a server-rendered page would flash the default variant. Write the saved variant into the page before it is sent: put a placeholder that isn't one of SvelteKit's own `%sveltekit.*%` in `src/app.html` (`<html lang="en" data-variant="%variant%">`), and fill it in `src/hooks.server.ts` with `transformPageChunk`. A cookie is the visitor's text, so check it before it goes into the page, and give `replace` a function so a `$&` in it isn't read as a pattern:

```ts
import type { Handle } from '@sveltejs/kit'

const VARIANT = /^[a-z0-9-]+$/

export const handle: Handle = async ({ event, resolve }) => {
  const saved = event.cookies.get('variant') ?? ''
  const variant = VARIANT.test(saved) ? saved : ''
  return resolve(event, {
    transformPageChunk: ({ html }) => html.replace('%variant%', () => variant),
  })
}
```

A file has one `handle`. If the app sets the language and direction too ([platform rules](platform.md#right-to-left)), or already has its own `handle`, don't add a second: put the variant in the same `transformPageChunk` (platform.md shows the three together), or join the hooks with `sequence` from `@sveltejs/kit/hooks`.

An empty `data-variant=""` matches no variant, so the default shows. A prerendered page (`adapter-static`) has no cookie at build time: apply the saved variant from the effect, or from a small inline script in `app.html`, before the first paint. In Vite, apply a saved variant in `src/main.ts` before `mount`, so no one sees the default first. Set both attributes on `<html>`: the variant selectors are scoped to `:root`.

## Fonts

`motif tokens --json` lists the theme's `fonts`: each family with the weights its roles use. Load each one with its Fontsource package, and import each weight once:

```bash
npm install @fontsource/onest
```

In `+layout.svelte` (Vite: `src/main.ts`), after the Motif import:

```ts
import '@fontsource/onest/400.css'
import '@fontsource/onest/600.css'
```

The package name is the family in lower case with hyphens (`@fontsource/source-serif-4`). An Arabic companion, second in the font list, loads the same way. Don't use `@fontsource-variable` for theme fonts: it registers the family under another name, so the theme's names wouldn't match.

A font with no Fontsource package is served with the app: files and licence in `static/fonts/` (Vite: `public/fonts/`), declared once with `@font-face` under the exact family name the theme uses, in a stylesheet the root imports.

## Tailwind v3

Motif writes the CSS variables only. Use them as `bg-[var(--motif-color-action-primary)]`, or upgrade to Tailwind v4 for the generated theme.
