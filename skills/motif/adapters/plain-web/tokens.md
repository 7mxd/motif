# Theme code

What `motif tokens` writes for a plain web site, how to link it, and how pages use the theme values.

## What motif tokens writes

| File | Holds |
|---|---|
| `motif.css` in the site folder | A CSS variable per role: `--motif-color-action-primary`, `--motif-space-4`, `--motif-font-body-size` and so on. Light values sit on `:root`; dark values apply under `prefers-color-scheme: dark` and on `[data-theme="dark"]`; `[data-theme="light"]` forces light. When the design guide has variants, each also gets `:root[data-variant="<id>"]` blocks for light and dark. It also stops CSS animations and transitions for people who ask for reduced motion. |
| `design/generated/tokens.flat.json` | Every value, springs included, for scripts that need numbers. |

Both start with a "Generated by Motif" line. Never edit them: change `design/tokens.json`, then run `motif tokens` again.

## Linking it, once per page

Link `motif.css` in each page's `<head>`, before the site's own stylesheets, with a path relative to the page:

```html
<link rel="stylesheet" href="motif.css">
<link rel="stylesheet" href="components.css">
<link rel="stylesheet" href="styles.css">
```

A page in a subfolder links `../motif.css`. `motif tokens` reminds you while no page links it.

## Using the values

Every colour, size, corner, shadow, font and timing comes from a variable:

```css
.notice {
  padding: var(--motif-space-4);
  border: 1px solid var(--motif-color-border);
  border-radius: var(--motif-radius-md);
  background: var(--motif-color-surface);
  color: var(--motif-color-text-primary);
  font-family: var(--motif-font-body-family);
  font-size: var(--motif-font-body-size);
  line-height: var(--motif-font-body-line-height);
}
```

| Role | CSS |
|---|---|
| `color.background` | `var(--motif-color-background)` |
| `color.action-primary` with `color.on-action-primary` | `var(--motif-color-action-primary)` and `var(--motif-color-on-action-primary)` |
| `space.4` | `var(--motif-space-4)` |
| `radius.md` | `var(--motif-radius-md)` |
| `shadow.md` | `var(--motif-shadow-md)` |
| `font.body` | `var(--motif-font-body-family)`, `-size`, `-weight` and `-line-height` |
| `font.mono` (optional, for code) | `code, kbd, samp, pre { font-family: var(--motif-font-mono-family, ui-monospace, monospace); }` (the fallback covers a theme without the role) |
| `duration.base`, `easing.standard` | `var(--motif-duration-base)`, `var(--motif-easing-standard)` |

Lengths that aren't design values stay as they are: a `1px` border, a `40rem` maximum width, a `3rem` minimum height for touch targets.

## The site's own names

An existing site often has its own variables (`--bg`, `--muted`). Keep the names, and define each one from a role once, in one `:root` block:

```css
:root {
  --bg: var(--motif-color-background);
  --surface: var(--motif-color-surface);
  --muted: var(--motif-color-text-secondary);
  --accent: var(--motif-color-action-primary);
}
```

Every `var(--bg)` in the site is then a theme value, and `motif check` stops reporting it. A variable set to a typed colour (`--bg: #f2f2f7`) is still reported. Delete the site's own dark-mode blocks once its variables point at roles: `motif.css` switches the roles. `motif extract` lists the site's variables in `design/extract-report.json`, with the role each one matches.

Colours that are the user's own data (a colour they picked for their card, say) aren't theme values: mark those lines `motif-ok` with the reason ([checks](checks.md)).

## Dark mode

Dark mode follows the system automatically. To offer a switch, set `data-theme` on `<html>` and remember the choice. The saved choice is applied by a small script in `<head>`, before the page is drawn; in `app.js` (loaded with `defer`) it would run after, and the page would flash in the other theme first:

```html
<script>
  try {
    const theme = localStorage.getItem("theme");
    if (theme) document.documentElement.dataset.theme = theme;
  } catch {}
</script>
```

The `try` block keeps its name to itself (a global `const` would clash with one of the same name in `app.js` and stop it) and lets the page draw when storage is blocked. A site whose security policy blocks inline scripts loads the same lines from a `theme.js` in `<head>`, without `defer`.

The switch itself goes in `app.js`:

```js
function setTheme(theme) {
  document.documentElement.dataset.theme = theme;
  localStorage.setItem("theme", theme);
}

function followSystem() {
  delete document.documentElement.dataset.theme;
  localStorage.removeItem("theme");
}
```

Never write your own `prefers-color-scheme` rules for colours: the roles already change.

## Variants

When the design guide has variants, choose one by setting `data-variant="<id>"` on `<html>`, the same element as `data-theme`; they combine with each other and with the system's dark setting. The default variant needs no attribute. Pages keep using the same `var(--motif-…)` variables and need no per-variant CSS.

Variant selectors are scoped to `:root`, so an inner element with its own `data-theme` doesn't keep the variant: set both on `<html>`. Save the choice and apply it in the same `<head>` script as the theme, so the page doesn't flash in the default first:

```html
<script>
  try {
    const variant = localStorage.getItem("variant");
    if (variant) document.documentElement.dataset.variant = variant;
  } catch {}
</script>
```

Switching is `document.documentElement.dataset.variant = id` plus `localStorage.setItem("variant", id)`; deleting the attribute returns to the default.

## Fonts

`motif tokens --json` lists the theme's `fonts`: each family with the weights its roles use (fonts every computer has are left out). Load each one either way:

**From the site's own folder** (nothing loads from another server). Put the font file and its licence in `fonts/`, and declare it once at the top of `styles.css`. A variable font covers every weight with one file:

```css
@font-face {
  font-family: "Nunito";
  font-style: normal;
  font-display: swap;
  font-weight: 200 1000;
  src: url("fonts/nunito.woff2") format("woff2");
}
```

Fontsource has the files for every Google font, with their licences (`fontsource.org`).

For an Arabic companion, copy only its Arabic file from Fontsource's variable package (`<id>-arabic-wght-normal.woff2`, such as `readex-pro-arabic-wght-normal.woff2`) and add the `unicode-range` line from Fontsource's CSS for that file, so it's used for Arabic letters only. A Google Fonts link does this by itself.

**A project font.** A font named under `fonts` in the design guide is already in the project, at the paths the guide lists. `motif tokens` downloads nothing and the page loads it itself: declare it with `@font-face` under the guide's family name, with a `url()` relative to `styles.css` (add one `@font-face` per weight and style, with its `font-weight` and `font-style` as the guide lists them; when the guide lists that weight and style in several formats, put them all in one `src`, WOFF2 first, each with its `format()`). Previews load the same files from the project.

**From Google Fonts.** One link per family in each page's `<head>`, before `motif.css`:

```html
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Nunito:wght@400;600;700&display=swap">
```

The family name must match the theme's exactly, or text falls back to the system font.

## Springs

CSS has no springs. Use the duration and easing roles in CSS. A script that animates with springs reads them from `design/generated/tokens.flat.json`.
