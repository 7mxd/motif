# Motif 1.3: States That Know Their Screens — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `motif shot --state` runs each state only on the screens its script names, skips a shot when the script returns `false`, and never loses a state silently, on every stack.

**Architecture:** One shared module (`cli/src/shot/state-screens.ts`) reads the `// motif-screens:` line, matches screens and sums up each state's outcome. The web capture loop and the three native shot planners filter with it before anything runs. The web page script and the three native harnesses report "not here" shots back as `RouteResult.notHere`. `runShot` turns that into notes, a JSON `stateResults` field and the exit status. The skill's modes and the nine stack guides teach the agent to write the line and `return false`.

**Tech Stack:** Bun + TypeScript (CLI, `bun test`), Chrome via CDP (web capture), Dart/flutter_test, Kotlin/Compose test rule, Swift/XCTest harnesses.

**Spec:** `docs/specs/2026-11-02-motif-1.3-state-screens-design.md`

## Global Constraints

- Line: `// motif-screens: <screen>, <screen>` in the script's leading region (comments, blank lines, and in Dart/Kotlin/Swift `import`/`package`/`part`/`library` lines). Read nowhere else.
- `*` matches exactly one path segment. Matching ignores a trailing slash and anything from the first `?`. Lines match the route as requested (as given to `--routes` or found by discovery), never the landed-on address. Hash routes (`/#/applications/42`) are plain segments.
- "Not here" is `return false` in every language. `return;`, no value, a normal finish and a no-value signature all mean "captured", as in 1.2.
- A state with no line runs on every screen (1.2 behaviour), plus one note.
- *Not in this run* (the line names no screen in this run): a note; exit status unchanged. *Lost* (it was tried on a named screen and returned `false` in every shot of that screen, or it has no line and returned `false` everywhere): a note naming the state and screen, and exit 1.
- "Not here" is per shot. A skipped shot is never reported as missing or as a failed comparison (`--against`, SwiftUI `missing`).
- The JSON changes only by addition: `stateResults` on the run, `notHere` on a route.
- Copy follows the existing `motif shot` notes: plain words, says what to do next.
- Ask the owner before any release.

## Review Focus

1. A line whose screens use a different form from the run's routes (`/applications/*` when the app is hash-routed as `/#/applications/42`): the state is "not in this run", and the note shows both the line and the run's routes so the mismatch is obvious. Test in Task 3.
2. `--rtl` and `--variant` looks: a state on `/` still runs on the `/ar` look and every variant (requested route, not landed). Test in Task 2.
3. A phone-only sheet (`false` at desktop width, captured on phones): not lost, and `stateResults` lists the desktop shots under `notHere`. Test in Task 3.
4. `--states-only` with every state lined to one page: only that page is opened; a page no state names is never loaded. Test in Task 2.
5. `--against` a 1.2 "before" set that holds copies: there are no "missing" notes, and the comparison count equals the shots taken. Test in Task 3.
