### Task 1: An Arabic companion survives a generic first family

**Files:** `cli/src/generate/theme-fonts.ts` (`stackFamilies`) and each native generator that reads it: `cli/src/stacks/{swiftui,compose,flutter,react-native}/generate.ts`. Tests in each stack's generate test and `theme-fonts` tests.

- `stackFamilies("system-ui, Readex Pro")` returns `[]` today (theme-fonts.ts:~38), so every native generator drops the companion silently. On native, "the system font for Latin, a bundled Arabic font for Arabic" is the most natural stack to write.
- Fix: a leading generic keyword means "the platform's system font", and later named families are still read. A native generator then draws Latin text in the system font and Arabic text in the companion. On the web, CSS already handles the whole stack, so web output stays byte-identical.
- Tests: for each native stack, a guide with `"system-ui, Readex Pro"` gets the companion in its generated theme, and its project-font notes no longer call the bundled font unused (`cli/src/contract/fonts.ts:~78`). Every existing snapshot stays unchanged.
- Commit: `fix(tokens): a type stack that starts with the system font keeps its Arabic companion on every native stack`.

### Task 2: A drafted text colour never fails the drafted background

**Files:** the shared draft code (`cli/src/extract/draft.ts` and its colour-role picking); tests in `draft` tests.

- Landmarks's only text colour found was `.white`, on photos, so both text roles drafted as white on a white background, and the guide failed 14 checks until edited by hand. This draft logic is shared by every stack.
- Fix: when a found colour for a text role fails contrast against the drafted background (and surface) for that scheme, keep the default for that role and say which colour was set aside and why, in the draft's notes.
- Tests: a draft whose only text colour is white on a light background validates with no contrast problems, and its notes name the white. A draft whose found text colour passes keeps it, with output byte-identical to today's.
- Commit: `fix(extract): a found text colour that fails the drafted background is set aside, and the draft says so`.

### Task 3: A bundled font isn't drafted as a Google font

**Files:** extract on Flutter and Compose, and check React Native and SwiftUI too: `cli/src/stacks/*/extract.ts`, font detection, `cli/src/contract/fonts.ts`.

- From the 2E/2F final reviews: a family the app bundles (asset or res/font files) is drafted as a Google family, so `motif tokens` points the app at Google instead of its own files.
- Fix: a family whose files the app ships is drafted as the app's own (a project font). A family is drafted as Google only when the app gets it from Google: a package such as google_fonts or @expo-google-fonts, or a download.
- Tests: on each stack, one bundled family and one Google family each get the right source.
- Commit: `fix(extract): a font the app ships is drafted as its own, not as a Google font`.

### Task 4: `--variant all` on a guide with one palette draws the default

**Files:** wherever `--variant` is parsed for `shot` and `preview` (`cli/src/commands/shot.ts`, `preview`, the stacks' variant handling); tests in the shot and preview command tests.

- Today it's refused with "This design guide has no variants." (exit 2) and no next step, on every stack and in `preview` (Expo hands-on problem 3). Agents run `--variant all` by habit, as the review mode tells them to.
- Fix: `--variant all` on a guide without variants draws the default, as if `--variant` were absent, and adds a one-line note ("This design guide has one palette, so --variant all drew it."). A named variant the guide lacks is still refused, with a next step that lists the variants or says to leave `--variant` out.
- Tests: shot and preview, on a web guide and a native stack (fake runner), each with `all`, a missing name, and no flag.
- Commit: `fix(shot): --variant all on a guide with one palette draws it and says so`.

### Task 5: Expo's open problems 5, 6 and 7

**Files:** `cli/src/stacks/react-native/extract.ts` (5); the shared type-role drafting (6, `cli/src/extract/draft.ts` or the type sampler); the dark-equals-light note in shot (7, `cli/src/shot/*` and wherever the identical-variant note is decided).

- **5.** HiSalon loads Thmanyah Sans with `useFonts(fontAssets)`, where `fontAssets` is an object defined elsewhere with `require("…ttf")` entries. Extract reads only inline `useFonts({ … })` and `@expo-google-fonts` imports, so the draft has no Arabic companion. Fix: follow an identifier passed to `useFonts` to its object literal in the same file, or in an imported module of the app. Read its `require` entries as bundled families, and draft the Arabic one as the companion, as inline objects already are.
- **6.** The draft's type roles miss the commonest small sizes. Caption is 10 px while 12 px (22 uses) and 11 px (11 uses) are common, so check suggests `type.label (13px)` for 12 px text. Fix: the smallest roles are drawn from sizes by use count, so that a frequently used small size becomes a role. Pin it with the HiSalon-shaped sample counts. Check that other stacks' drafts change only where the same mistake happened, and say which.
- **7.** "Dark looks like light" needs byte-identical pictures. HiSalon's spinners make each dark screenshot differ by a few pixels, so the note isn't given. The identical-variant note has the same weakness. Fix: compare with a tolerance. Treat the pair as the same when nearly all pixels match, e.g. at most 0.5% differ beyond a small per-channel threshold. Both notes use the same comparison.
- Tests for each. Commit one per problem: `fix(extract): …`, `fix(extract): …`, `fix(shot): …`.

- Commits per item. Prove the Swift side on the Mac.

### Task 7: The eval runner on older Claude Code, and the Node check

**Files:** `tests/evals/run.ts` (purge), `tests/evals/preflight.ts` (Node); tests in `evals-run`, `evals-preflight`.

- `claude purge -y <dir>` fails on Claude Code before purge existed (2.1.283 on the Mac: "unknown option '-y'"), so each case's Claude Code project data is left. Fix:
  - preflight reads `claude --version` and records whether purge is available;

- Node 20.9 with npm is required even for a run of SwiftUI cases, which install nothing with npm. Fix: require Node only when a chosen case needs it (web, React Native, the plugin build if it does), and test both.
- Commit per item.
