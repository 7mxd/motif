# Motif 2.0 First Impressions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (owner chose Native) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Motif's sign-in and welcome screens beat a plain agent build: two accent colours, a hero type role, depth and sign-in library pieces, one signature detail per style, recipe-style guidance, and a `text-fit` audit rule.

**Architecture:** New optional roles go through the existing optional-role path (`OPTIONAL_ROLES`, `BRAND_PAIRS`-style pair list, preset builder); every stack's generator already emits all roles generically. Library and knowledge changes are skill text checked by `skill-lint.ts` and `library.test.ts`. `text-fit` joins the web audit's in-page script and the three native harnesses as a new `IssueRule`.

**Tech Stack:** Bun + TypeScript (`cli/`), Dart / Kotlin / Swift harness files, Markdown skill text.

**Spec:** `docs/specs/2026-11-10-motif-2.0-first-impressions-design.md`

## Global Constraints

- New colour roles are named exactly `accent` and `accent-2`; each has a dark value; pairs `text-primary` on `accent` and `text-primary` on `accent-2`, kind `text` (4.5:1).
- Accents never fill buttons, links or focus; area cap: brand + accents ≤ about a third of a screen, each accent ≤ about a tenth.
- New font role is named exactly `hero`, family `{primitive.font.display}`, line height 1.05, size 56–72 on the web per preset, a step above that preset's `display`.
- At most one depth piece per screen, first-impression screens only.
- No skill line names a test brief (stride, ledgerly, bloom, sahm, nabta, rihla, darb, nuzha, sanad, masar) or its content.
- Every library piece covers all nine stacks: react-web, plain-web, vue, svelte, angular, flutter, compose, react-native, swiftui.
- Do not change B/C/D tests, fixtures or graders.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; no model ids elsewhere.

## Review Focus

1. A theme made before 2.0 (no `accent`, `accent-2`, `hero`) must still validate, generate and preview: the preview kit falls back (`accent` → `brand-soft` → `action-secondary`; `hero` → `display`). Test in Task 1 and Task 2.
2. Dark mode: every preset's dark `accent`/`accent-2` passes 4.5:1 under dark `text-primary`. Test in Task 1.
3. `text-fit` must not fire on text that is intentionally one word per line because the box is narrow by design for single words (a one-word label), nor on a visually-hidden screen-reader label (`clip: rect(0 0 0 0)`, 1×1 px). Test in Task 3.
4. `text-fit` on right-to-left pages: truncation measured the same way. Test in Task 3.
5. A project that already defined its own `accent` colour (a custom role) keeps it: `motif validate` only checks the type, never overwrites. Test in Task 1.

### Task 3: `text-fit` in the web audit

**Files:**
- Modify: `cli/src/shot/audit.ts:6` (`IssueRule` gains `"text-fit"`), `installAudit` (add `textFit()`), `auditPage` (call it in light scheme, both viewports), `judge` (case `"text-fit"`)
- Test: `cli/test/text-fit.test.ts` (browser, `describe.skipIf(!browser)` like `cdp.test.ts`), `cli/test/audit.test.ts` (judge/toFindings)

**Interfaces:**
- Produces: `RawIssue` with `rule: "text-fit"`, `kind` from the element, `label` = the full text, and new optional field `fit?: "cut" | "broken"`.

`textFit()` reports:
- **cut:** element with direct text where `scrollWidth > clientWidth + 1` and computed `text-overflow` is `ellipsis`, or `overflow` is `hidden`/`clip` with `white-space: nowrap`; or `-webkit-line-clamp` set and `scrollHeight > clientHeight + 1`. Skip visually-hidden elements (width or height ≤ 1, or `clip`/`clip-path` hiding them).
- **broken:** text of 2–3 words (split on whitespace) whose rendered line count (via `Range.getClientRects()` distinct tops) equals its word count. Skip one-word text.

Severity: major for `h1–h6`, buttons, links styled as buttons, `[role=tab]`, chips (element with border-radius ≥ half its height), and card titles (first heading-like child of an element with a border or shadow); minor otherwise. Summary: `"<label>" is cut off` / `"<label>" breaks one word per line`. Fix: "Shorten the copy, or let it wrap once and give the row room."

- [ ] **Step 1: Failing browser tests** on an inline HTML page: a 60px `<button>` with "Thursday Tempo" and `text-overflow: ellipsis` → one cut, major; a 40px `<span>` "18 days late" → one broken; a clean page → none; a one-word narrow label → none; an `.sr-only` label → none (Review Focus 3); the same cut button under `dir="rtl"` → one cut (Review Focus 4).
- [ ] **Step 2: Run** `bun test test/text-fit.test.ts` — fail.
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run** `bun test test/text-fit.test.ts test/audit.test.ts` — pass.
