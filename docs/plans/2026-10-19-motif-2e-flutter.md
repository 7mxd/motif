# Motif 2E — Flutter (Phase A, first stack) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Flutter gets the full experience of the parity checklist (spec §4): detection inside monorepos, a toolchain check, theme code in Dart with every variant, checks of Dart code, a draft guide from an existing Flutter theme, screenshots and audits rendered by `flutter test` with no device, a stack guide, fixtures and evals. Along the way the two web stacks gain what the checklist asks of every stack and they lack today: right-to-left screenshots and an accessible-name audit.

**Architecture:** A stack's exact half lives in `cli/src/stacks/<stack>/` behind a small `NativeStack` interface (`cli/src/stacks/native.ts`) that `tokens`, `check`, `extract`, `shot` and `doctor` dispatch to; React web and plain web keep their current code paths. Dart is read with its own comment-and-string masker and rules that report `Hit`s like the web rules, so grouping, exceptions, suggestions and JSON output are unchanged. Screenshots come from a Dart harness that Motif writes into `<app>/.motif/shot/` (git-ignored) and runs with `flutter test`. It pumps the app per screen, size, scheme, variant and direction, writes PNGs, and writes a `result.json` that `shot` maps onto its existing `RouteResult` and `AuditIssue` types. Everything after capture (audit file, compare, save) is shared.

**Tech Stack:** Bun + TypeScript (`cli/`), Dart/Flutter 3.27+ for the harness and generated code, Markdown (`skill/`), `bun test`, `flutter test` / `flutter analyze` in tests that skip without Flutter.

**Spec:** `docs/specs/2026-10-19-motif-part2-all-stacks-design.md`: §4 (parity), §6 (common) and §6.1 (Flutter), §8 (monorepos), §9 (fixtures and evals), §10 (tool and CI), §11 (delivery). Phase 0 (plan 2D) is merged: variants (`cli/src/contract/variants.ts`), `ThemeSet` (`cli/src/generate/theme.ts`) and project fonts (`cli/src/contract/fonts.ts`) are the interfaces this plan builds on.

**Phase A is four plans:** 2E Flutter (this), then 2F Jetpack Compose, 2G SwiftUI and 2H React Native (Expo). Each is written after the one before it is merged, so it can reuse what that one built (`NativeStack`, `--rtl`, the name audit). v0.5.0 ships when the four are done or, per spec §11, without a stack whose parity row is still open.

## Global Constraints

- Nothing changes for an existing React web or plain web user except the additions named here (`--rtl`, the accessible-name audit, the identical-variant note). Their generated files stay byte-identical, and existing tests pass unchanged unless a task names the test it edits.
- Flutter 3.27 or later (Dart 3.6). The generated Dart and the harness compile with `flutter analyze` showing no errors or warnings on the fixture app.
- Generated Dart files start with the existing `TS_HEADER` line (`// Generated by Motif — edit design/tokens.json instead, then run "motif tokens".`), so `isMotifGenerated`, protection and `generated-edited` work unchanged.
- Motif never edits `pubspec.yaml`, `lib/main.dart` or any file it didn't generate. Registration it needs (fonts, `google_fonts`) is printed as a one-step note.
- The harness lives only in `<app>/.motif/` with a `.gitignore` of `*`, and Motif deletes the run's generated test file when the run ends, whatever the outcome. Screenshots go to `design/shots/` as on the web.
- Variant ids become Dart identifiers by camelCase, and a reserved word gets `Variant` appended (decision 0006): `default` → `defaultVariant`, `partner-store` → `partnerStore`.
- Screenshot names: `<slug>[@<state>][+<variant>].<size>[.rtl][.dark].png`, for example `home@filled+men.mobile.rtl.dark.png`. The RTL segment comes after the size and before `.dark`.
- Tests that need Flutter, or a browser, skip with a reason when it's missing (`test.skipIf(!hasFlutter)`, with `hasFlutter` from a helper that runs `flutter --version` once).
- Messages are plain words in Motif's voice, and every refusal says what to do next.
- Commits end with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`. Work on a branch (`plan/2e-flutter`), and never push without the developer asking.

## Review Focus

1. **A monorepo shaped like HiSalon.** A pnpm workspace root with a `mobile/` folder holding two Flutter apps, a shared Flutter package and an Expo app: doctor lists all three apps and not the package, and `tokens` can write one theme into the shared package for both apps. Tests in Task 1 and Task 4.
2. **Dart text that only looks like a value.** `Color(0xFF…)` inside a string, a comment, a `///` doc comment or a raw string, a `Duration(seconds: 2)` given to a timer, or `Colors.transparent` must not be findings. `Colors.white` in a widget and `Curves.easeIn` in a `curve:` must be. Tests in Task 3 and Task 5.
3. **An app that can't start in a test.** Its `main()` initialises plugins, reads secure storage or calls an API. The harness stubs what it knows, answers HTTP from `design/states/http.json`, and reports what it couldn't reach in plain words, per screen, without failing the whole run. Tests in Task 9.
4. **Variants the app switches itself** (HiSalon switches palettes by the customer's gender, not through Motif's theme). The setup script gets the variant id. When a variant's screenshots are byte-identical to the default's on every screen, `shot` says so, on every stack. Tests in Task 7 and Task 9.
5. **An Arabic run on an app without Arabic in `supportedLocales`.** The RTL shots are still taken, and `shot` says the app doesn't offer Arabic, so they show it left to right. Test in Task 9.

### Task 5: `motif check` on Flutter apps

**Files:**
- Create: `cli/src/stacks/flutter/rules.ts`
- Modify: `cli/src/stacks/flutter/index.ts`, `cli/src/check/run.ts`, `cli/src/commands/check.ts`, `cli/src/check/suggest.ts`

**Interfaces:**
- Consumes: Tasks 1, 3 and 4. `buildScale(theme, srcDir)`, `suggestRole`, `exceptionFor` and `generatedEditedHits` are used unchanged.
- Produces: `scanDart(file, scale): Hit[]`, run on the masked text with positions in the original. All rules use the existing rule ids:
  - **raw-color** (always a violation):
    - `Color(0x…)`, `Color.fromARGB(`, `Color.fromRGBO(`, `Color.from(`, `Colors.<name>[.shadeN]` other than `Colors.transparent`, and `CupertinoColors.<name>`.
    - `value` is CSS hex (`0xAARRGGBB` becomes `#rrggbb`, or `#rrggbbaa` when alpha isn't FF; `Colors.white` is `#ffffff`, `Colors.black` is `#000000`); there is no value for other named colours.
    - `context` comes from the nearest named argument and constructor:
      - background: `backgroundColor`, `fillColor`, `scaffoldBackgroundColor`, `canvasColor`, and `color` inside `Container(`, `BoxDecoration(`, `Material(`, `Card(` or `ColoredBox(`;
      - text: `foregroundColor`, `iconColor`, `cursorColor`, and `color` inside `TextStyle(` or `Icon(`;
      - border: `color` inside `BorderSide(` or `Border.all(`, and `borderColor`;
      - other: everything else.
  - **off-scale**, a violation only off the theme's scale (on the scale is `violation: false`, as on the web; 0 is always allowed):
    - kind `space`: the numbers in `EdgeInsets.all/symmetric/only/fromLTRB`, `EdgeInsetsDirectional.only/fromSTEB`, a `SizedBox(` with only `width:` or only `height:` and no `child:`, `Gap(`, and `spacing:`, `runSpacing:`, `mainAxisSpacing:`, `crossAxisSpacing:`;
    - kind `radius`: `BorderRadius.circular(`, `BorderRadiusDirectional.circular(`, `Radius.circular(`;
    - kind `font-size`: `fontSize:`.
  - **raw-font:** `fontFamily: '<literal>'`, string literals in `fontFamilyFallback: [`, and `GoogleFonts.<family>(` / `GoogleFonts.getFont('…'`.
  - **raw-motion:**
    - kind `duration`: a `Duration(milliseconds|seconds: N)` that is the value of a named argument ending in `uration` (`duration:`, `reverseDuration:`, `transitionDuration:`…). It is a violation only off the theme's durations. Other Durations (timers, timeouts) are not read.
    - kind `easing`: `Curves.<name>` other than `Curves.linear`, and `Cubic(` literals.
    - kind `spring`: `SpringDescription(` and `SpringDescription.withDampingRatio(`.
  - **reduced-motion** (app-wide, from `FLUTTER.appWide`): the app animates (`AnimationController(`, `Animated[A-Z]\w*(`, `TweenAnimationBuilder`, `.animate(`, `Hero(`) but no file mentions `disableAnimations` or `MotifMotion.`. One hit at the first animation, with the message "Animations here ignore the "reduce motion" setting." and the fix "Use MotifMotion.duration(context, …) for durations (it is zero when reduce motion is on), or check MediaQuery.disableAnimationsOf(context)."
  - **generated-edited:** the expected files are `generateFlutter` at the app's `themeDir`.
