# Motif 2F — Jetpack Compose (Phase A, second stack) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jetpack Compose gets the full experience of the parity checklist (spec §4): detection inside monorepos and a toolchain check, Kotlin theme code with every variant, checks of Kotlin code, a draft guide from an existing Compose theme, screenshots and audits rendered on the JVM with no device or emulator, a stack guide, fixtures and evals.

**Architecture:** Compose is the second `NativeStack` (`cli/src/stacks/native.ts`), in `cli/src/stacks/compose/`, built the way Flutter was (plan 2E): `tokens`, `check`, `extract`, `shot` and `doctor` already dispatch to a native stack, so this plan fills in the Compose methods and touches shared code only where Flutter-only assumptions remain. Kotlin is read with its own comment-and-string masker. Screenshots come from a Kotlin test that Motif writes into `<module>/.motif/shot/` (git-ignored) and runs with the app's own Gradle wrapper. A Gradle init script that Motif passes with `-I` adds the test source folder and the test libraries for that run only, so the developer's build files are never edited. Robolectric draws the app's composables on the JVM with its native graphics, and Android's Accessibility Test Framework (ATF) audits them. The harness writes PNGs and a `result.json` in the same shape as Flutter's, which `shot` already maps onto `RouteResult` and `AuditIssue`.

**Tech Stack:** Bun + TypeScript (`cli/`), Kotlin 2.0+ with the Compose compiler plugin, Jetpack Compose (Compose UI 1.9+, Material 3), Gradle (the app's wrapper), Robolectric (native graphics), ATF, `bun test`, Gradle in tests that skip without a JDK and the Android SDK.

**Spec:** `docs/specs/2026-10-19-motif-part2-all-stacks-design.md`: §4 (parity), §6 (common) and §6.2 (Compose), §8 (monorepos), §9 (fixtures and evals), §10 (tool and CI), §11 (delivery), §12 (the renderer is the builder's call, recorded as a decision). Plan 2E is merged: `NativeStack`, `--rtl`, the accessible-name audit, the identical-variant note, `readStates`, the result format of `cli/src/stacks/flutter/shot.ts` and decision 0007 are the patterns this plan follows.

**Phase A's remaining plans:** 2F Compose (this), 2G React Native (Expo), 2H SwiftUI. Each is written after the one before it is merged.

## Global Constraints

- Nothing changes for React web, plain web or Flutter users. Their generated files stay byte-identical, and existing tests pass unchanged unless a task names the test it edits.
- Floors: Kotlin 2.0 (the Compose compiler Gradle plugin), Compose UI 1.9 (`Modifier.dropShadow`), Material 3 1.3, Android Gradle Plugin 8.6 (raised from 8.5 by decision 0008: Compose UI 1.9 requires it), JDK 17, `compileSdk` 35. Task 8's spike confirms each and records it in decision 0008; a floor it can't meet is lowered or raised there, with the reason, and `doctor` and the guide say the same.
- Generated Kotlin files start with `TS_HEADER` (a `//` comment line), so `isMotifGenerated`, protection and `generated-edited` work unchanged. Generated Android XML resources start with `<!-- Generated by Motif — edit design/tokens.json instead, then run "motif tokens". -->`, which `isMotifGenerated` learns to recognise (Task 4).
- Motif never edits `build.gradle(.kts)`, `settings.gradle(.kts)`, `libs.versions.toml`, `AndroidManifest.xml` or any file it didn't generate. A dependency it needs (`ui-text-google-fonts`) is printed as a one-step note with the exact line for the version catalogue and the module's dependencies.
- The harness lives only in `<module>/.motif/` with a `.gitignore` of `*`, plus the init script in the same folder; Motif deletes the run's generated test sources and init script when the run ends, whatever the outcome. Gradle's own outputs go under `<module>/build/`, which the app already ignores. Screenshots go to `design/shots/`.
- Variant ids become Kotlin enum entries in UpperCamelCase (`default` → `Default`, `partner-store` → `PartnerStore`), which no Kotlin keyword can clash with; `checkVariants`' clash check (decision 0006) uses the same form for Compose. Colour roles become lowerCamelCase properties (`text-secondary` → `textSecondary`).
- Screenshot names follow 2E: `<slug>[@<state>][+<variant>].<size>[.rtl][.dark].png`.
- Tests that need a JDK and the Android SDK skip with a reason when either is missing (`test.skipIf(!hasAndroid())`, with `hasAndroid` in `cli/test/helpers.ts` checking once for `java` (or `JAVA_HOME`, or Android Studio's bundled JBR) and an SDK folder with `platforms/`).
- Messages are plain words in Motif's voice, and every refusal says what to do next.
- Commits end with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`. Work on the branch `plan/2f-compose`; never push without the developer asking.

## Review Focus

1. **An Android project shaped like Android Studio's template.** `settings.gradle.kts` at the root with `include(":app")`, the module in `app/`, a version catalogue in `gradle/libs.versions.toml`, `namespace = "com.example.rafiq"` in `app/build.gradle.kts`, sources in `app/src/main/java/com/example/rafiq/` (or `kotlin/`), and the template's own `ui/theme/Color.kt`, `Theme.kt`, `Type.kt`. Doctor lists the app at `app` (not the root), `tokens` writes beside the template's theme without touching it, and `extract` reads the template's `Purple80`-style colours and `lightColorScheme`/`darkColorScheme`. Tests in Tasks 1, 4 and 6.
2. **Kotlin text that only looks like a value.** `Color(0xFF…)` in a string, a `"""` raw string, a `/* /* nested */ */` comment or a KDoc; `${'$'}`-templates; `delay(300)` in a coroutine; `Color.Transparent` and `Color.Unspecified`; `16.dp` passed to `Spacer(Modifier.size(…))` of an icon. `Color.White` in a composable and `FastOutSlowInEasing` in a `tween` must be findings. Tests in Tasks 3 and 5.
3. **An app that can't start in a JVM test.** Its `Application` class initialises Firebase or Hilt, or its first screen reads from a ViewModel that calls the network. The harness draws `@Preview` composables without the activity, starts the activity only for routes, and reports what failed per screen in plain words, without failing the whole run. Tests in Task 9.
4. **Two variants and the app's own variant.** An app that calls `MotifTheme(variant = MotifVariant.Contrast)` itself is still drawn in the guide's default for the default's screenshots (the 2E lesson: the override is set for the default too). When a variant's screenshots are byte-identical to the default's, the existing note appears with Compose's `<how>`. Tests in Task 9.
5. **Gradle being slow or offline.** The first run downloads Robolectric's Android jars (hundreds of MB): the run says so before it starts, its time limit allows for it, and a run that fails because Gradle can't reach the network says that, not a stack trace. Tests in Task 9 (fake runner) and the spike's timings (Task 8).

    - `enum class MotifVariant { Default, … }`: only with variants, the default first.
    - `@Immutable data class MotifColors(val background: Color, …)`: one `Color` property per colour role in lowerCamelCase, and `companion object { val Light; val Dark; val <Variant>Light; val <Variant>Dark }`, colours written `Color(0xAARRGGBB)`.

    - `object MotifDurations { const val instant = 0; const val base = 200; … }` (milliseconds, `Int`), `object MotifEasing { val standard = CubicBezierEasing(0.2f, 0f, 0f, 1f); … }`, `object MotifSprings { fun <T> snappy(): SpringSpec<T> = spring(dampingRatio = …f, stiffness = …f); … }` with the ratio from `springPhysics` (`damping / (2 * sqrt(stiffness))`, mass 1), to 2 decimals.
    - `object MotifMotion { @Composable fun reduced(): Boolean` (true when `Settings.Global.ANIMATOR_DURATION_SCALE` is 0) and `@Composable fun duration(millis: Int): Int` (0 when reduced) `}`.
    - `object MotifType { val display: TextStyle; … }` for the guide's roles (size in `sp`, weight `FontWeight.W600`, `lineHeight` in `sp` from size × line height, letter spacing in `sp`), with the role's first family, and `val displayArabic` etc. only for roles whose font list has a companion.

It picks the colours (`MotifTheme.debugVariantOverride ?: variant`), provides `LocalMotifColors`, and calls `MaterialTheme(colorScheme = …, typography = …, shapes = …, content)`. The Arabic companion's styles are used when the locale's language is `ar`, `fa`, `ur`, `ps`, `ckb`, `sd` or `ug`.
