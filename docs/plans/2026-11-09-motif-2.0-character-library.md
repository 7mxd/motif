# Motif 2.0 (character, built-in library, nothing to set up) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Retire the three set-up design sources, rewrite the character and motion guidance so no screen is plain, and add a built-in library of pieces for all 9 stacks, all landing with tests.

**Architecture:** Three PRs, each from its own branch off main, each green before the next starts. PR 1 is CLI code (source catalog, `connect`, `doctor`) plus the skill text that names sources. PR 2 is skill guidance (`knowledge/`, adapters' `motion.md`, UX pattern guides). PR 3 is the new `skill/library/` folder, its structure test and the skill's selection step. Skill text is tested the repo's way: `covers()`/`toContain` content tests plus `skill-lint.ts`.

**Tech Stack:** Bun + TypeScript (`cli/`), `bun:test`, Markdown skill files.

**Spec:** `docs/specs/2026-11-08-motif-2.0-character-and-library-design.md` (approved by the owner 2026-11-09, section 10's six calls included).

## Global Constraints

- Full parity: every rule and every library piece covers all 9 stacks (react-web, plain-web, vue, svelte, angular, flutter, compose, react-native, swiftui); no stack gets a thinner version.
- All values from the guide's roles (colour, space, radius, type, duration, easing, spring roles); `motif check` passes on any adapted code.
- Accessibility: contrast, tap targets, reduced motion turns motion off, every chart has a text alternative (the key number in words).
- No runtime network fetches by Motif or by the agent following Motif; nothing to sign up for or connect.
- Licences: pieces are Motif's own writing; adapted ideas only from Magic UI (MIT), Uiverse galaxy repo (MIT), flutter_animate (BSD-3), Moti (MIT), with the licence notice kept in the piece. Never React Bits, Animate UI, Aceternity UI.
- Anti-goal "the C look": glowing charts, tilted 3D/glass cards, heavy gradient backdrops, colour on everything. One subtle gradient only where the Direction calls for it.
- Optional libraries (flutter_animate, Moti, Motion for React) only when the project already has them; otherwise the stack's built-in animation APIs (call 4).
- Skill file limits from `cli/test/skill-lint.ts`: `knowledge/*` ≤ 300 lines, other skill files ≤ 400, SKILL.md ≤ 500; links stay inside `skill/`; `knowledge/ux-patterns/*` keep exactly the sections Goal, Anatomy, Required states, Common mistakes, Mobile and web.
- Never weaken a test, fixture, grader or judge prompt. Tests for behaviour this plan deletes are deleted with it, and each PR description lists them by name.
- Branch + PR for every change; commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; no model identifiers elsewhere.
- Known failing test on Windows (the CLAUDE.md one) is an environment issue; CI on all three OSes is the gate.

## Review Focus

1. **A developer upgrading from 1.2 with 21st/Refero/60fps already in their agent settings.** `motif doctor` must still exit 0, list each retired source as "retired: you can remove it from <agent>'s settings", and never edit the file. Test in Task 2.
2. **A retired server whose name collides with Motion's pattern, or a settings file holding both Motion and a retired source.** Motion reports as connected, the retired one as retired, each once per agent. Test in Task 2.
3. **`motif connect` with an unknown id vs a retired id.** Unknown stays exit 2 `no-such-source`; retired is exit 0, no settings touched, even with `MOTIF_NO_CONNECT` unset. Test in Task 1.
4. **Reduced motion on every stack.** Each library motion piece's per-stack section names that stack's reduced-motion switch, and calm level drops stagger. Test in Task 7.
5. **A calm business brief (Ledgerly) still getting the plain screen.** The old sentence "Quiet business tools (invoicing, money, admin) keep their working screens plain" must be gone and the B floor stated. Test in Task 4.
