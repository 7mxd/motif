# Motif 2I — Vue and Nuxt (Phase B, first stack, with the web stacks' groundwork) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Vue 3 apps (Vite with Vue Router, and Nuxt 3 and 4) get the full experience of the parity checklist (spec §4): detection and a toolchain check, React web's CSS theme with Motion for Vue, checks of `.vue` files (templates, bindings and style blocks), a draft guide from an app's CSS and Vuetify themes, screenshots and audits through the app's own dev server, a stack guide, fixtures and evals. On the way it builds what Svelte (plan 2J) and Angular (plan 2K) reuse: a registry of web stacks and one module that reads component files.

**Architecture:** Two shared pieces first. `cli/src/stacks/web.ts` holds a `WebStack` registry, the web counterpart of `NativeStack`: each command asks it for the app's files, views, theme files, wiring note, routes, fixes and doctor items, so later web stacks add a folder, not branches in every command. React web and plain web keep their current code paths untouched. `cli/src/check/component-views.ts` generalises `htmlViews` (`check/html.ts`): a component file becomes same-length views (`css`, `script`, `markup`) with positions kept exact, plus the stack's bindings (`:style`, `:class`, `:transition`) placed in the script view, so every existing rule runs on them unchanged. Vue's theme code is React web's (`motif.css`, `motif.tailwind.css`, `motion.ts`, whose spring shape Motion for Vue takes as it is); screenshots reuse the browser pipeline with the app's `dev` script.

**Tech Stack:** Bun + TypeScript (`cli/`), Vue 3.5, Vite 8, vue-router 4 and 5 (with 5's file-based routes), Nuxt 3 and 4, Tailwind 4, motion-v 2 (Motion for Vue), Vuetify 3 (extract only), `bun test`, a real dev server in tests that skip without Node and a browser.

**Spec:** `docs/specs/2026-10-19-motif-part2-all-stacks-design.md`: §4, §7 (Phase B), §8, §9, §10 (the common module), §11 (delivery: a hands-on test on a public sample app). Phase A is released (v0.5.0); `NativeStack`, `--rtl`, the name audit, the default variant's `data-variant` attribute and the identical-variant note exist.

## Global Constraints

- Nothing changes for React web, plain web or the native stacks. Their generated files stay byte-identical, and existing tests pass unchanged unless a task names the test it edits.
- Floors: Vue 3 and Nuxt 3. Vue 2 and Nuxt 2 are a spec non-goal: `doctor` says so plainly (Task 1). Tailwind 4 for Motif's Tailwind theme (Tailwind 3 gets CSS variables only, with React web's note). motion-v 1 or later for `motion.ts`.
- Theme code is React web's, from the same functions: `motifCss(theme, variants)`, `tailwindCss(theme)` and `motionTs(theme)`. For the same guide the files' contents equal React web's. Variants switch through `data-variant` on `<html>`, as on the web.
- Motif never edits `package.json`, `vite.config.*`, `nuxt.config.*`, `app.config.*`, `main.ts`, `App.vue`, `app.vue` or any file it didn't generate. Wiring is a printed one-step note, as for React web.
- Theme files never land in the project's own `design/` folder (a Nuxt 3 app at the project root has its source folder there too; Task 3 says where they go instead).
- Generated files start with `CSS_HEADER` or `TS_HEADER`, so protection and `generated-edited` work unchanged.
- Screenshots use the app's own `dev` script (Vite, or `nuxt dev`), the web's sizes (`VIEWPORTS`, the desktop included), states as JavaScript, and axe's audit, unchanged.
- The shared modules (`stacks/web.ts`, `check/component-views.ts`) take no Vue-only shortcuts: a Svelte or Angular stack must be able to add its own bindings and files without editing them beyond a registry line.
- Messages are plain words in Motif's voice, and every refusal says what to do next.
