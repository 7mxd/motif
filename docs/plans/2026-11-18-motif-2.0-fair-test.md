# Motif 2.0: fair Test A, "no access", left/right check, design-rules additions — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Test A pairs compare one idea on both sides, let judges mark a side that didn't follow it, and add the
"no access" state, a left/right check on all 9 stacks, and six small skill-text rules, ready for one new full run.

**Architecture:** Briefs gain a `## Content` section that both sessions read. The eval harness reads it per screen,
shows it to the AI judges and the owner, and records an "off content" mark. `motif check` gets one new rule
(`physical-direction`) in a shared module with one scanner per source language, called from all three check paths and
gated by the project's `DESIGN.md`. The skill-text tasks are plain Markdown edits pinned by the existing skill tests.

**Tech Stack:** Bun + TypeScript (`cli/`, `tests/evals/`), `bun test`, Markdown skill files.

**Spec:** `docs/specs/2026-11-18-motif-2.0-fair-test-and-rtl-design.md` (§5.1–§5.5, calls 1–13 in §8). Evidence for §5.5:
`docs/specs/2026-11-18-chandra-design-rules-findings.md`.

## Global Constraints

- Full parity: the rule and every skill rule apply to React web, plain web, Vue, Svelte, Angular, React Native/Expo,
  Flutter, Compose and SwiftUI. No stack is "later".
- Rule id: `physical-direction`. Fix wording names the start/end form of the same stack.
- Skill text names no test brief or its content (`cli/test/skill-text.test.ts`), and no agent tool names outside
  adapters (skill lint).
- The Content section names nothing about Motif, design guides, tokens or components; no emoji; one intro line, verbatim:
  "Show exactly this content on these screens: no more items, no fewer, no other actions. How it looks and is laid out
  is up to you."
- Test A's bar (decision 0014) and the rubric's six design criteria don't change.
- Never weaken a test, fixture or grader to pass. A fixture change needs the owner's OK after he has seen the evidence
  (screenshot, problem boxed in red, by WhatsApp).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No push, PR, tag or release without the
  owner's explicit OK.
- Run tests from `cli/`: `bun test test/<file>`. Before any push: every file in `cli/test` except `fixtures-*` and
  `*e2e*`, in the background (~830 s); the known Windows CLAUDE.md failure is the only allowed failure.

## Review Focus

1. Text that says "left" without being layout ("3 seats left", `// was margin-left`, an `aria-label="Swipe left"`)
   must not be flagged → Task 1 tests `ignores comments and plain text`.
2. Classes or code that already handle direction (`rtl:ml-2`, `ltr:`, `[dir=rtl] &`, `EdgeInsetsDirectional`,
   `.leading`) must not be flagged → Task 1 test `ignores direction-aware forms`.
3. The 48 saved votes of run 20261113-052637 (no `offContent` field) must still load and score exactly as today
   (owner 48%, FAIL) → Task 6 test `old votes file still scores the same`.
4. A pair whose screen has no Content sub-heading (all runs before this change) gets no fold and the judge prompt
   without a content block → Task 3 test `screen without content` and Task 5 test `prompt without content`.
5. `DESIGN.md` with CRLF endings, or the accessibility heading worded differently ("## 7. Accessibility",
   "## Accessibility") → Task 2 test `start/end line is found whatever the heading and line endings`.
