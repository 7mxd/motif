# Motif v0.1.0 — Preview Release Design

- **Date:** 2026-10-17
- **Status:** Draft for review
- **Owner:** 7mxd
- **Scope:** the first published release of Motif: the `motif` tool and the Claude Code plugin, for React web apps and plain web sites. Packages for other agents (Part 3), the other stacks (Part 2) and Test A (Part 4) stay out ([core spec §4](2026-10-12-motif-core-design.md)).

---

## 1. Goal

Anyone with Claude Code installs Motif with two commands, and Motif fetches its own tool on first use, checked against the release's checksums, on Windows, macOS or Linux. Nobody builds from source or sets `MOTIF_BIN`.

Today the skill's bootstrap downloads the tool from the GitHub release `v<skill/VERSION>`, which has never been published, so trying Motif means building it ([plugin README](../../plugin/claude-code/README.md)).

**Done means:**

1. The GitHub release `v0.1.0`, marked **Pre-release**, holds the five tool binaries, the plugin zip, `SHA256SUMS`, `THIRD-PARTY-NOTICES.txt` and written release notes.
2. A post-release check passes on Windows, macOS and Linux: the plugin zip from the release matches `SHA256SUMS`, and `doctor` runs through the plugin's own bootstrap, which downloads and checks the tool from the release.
3. After the marketplace commit, a real install through Claude Code's plugin commands works on the developer's PC, in a separate Claude Code configuration.
4. The README tells people how to install it, and says it's a preview.
5. Nothing is tagged, published or pushed for users without the developer's approval at each step (§7).

## 2. Decisions

| Question | Decision |
|---|---|
| Agents | Claude Code only. Other agents are Part 3. |
| Stacks | React web and plain web, as built. |
| Label | GitHub **Pre-release**; the notes call it a preview and say what v1 still needs. |
| How the plugin ships | A zip attached to each release, next to the binaries. A marketplace file in the repo points at it, pinned by SHA-256. Nothing generated is committed. |
| Checks | CI on Windows, macOS and Linux after publishing, plus one real install on the developer's PC in a throwaway Claude Code configuration. |

## 3. What a release contains

Pushing a tag `v<version>` runs `.github/workflows/release.yml`. The release gets these assets:

| Asset | What it is |
|---|---|
| `motif-linux-x64`, `motif-linux-arm64`, `motif-windows-x64.exe`, `motif-darwin-arm64`, `motif-darwin-x64` | The tool, as built today |
| `motif-claude-code.zip` | **New.** The Claude Code plugin: the output of `bun run plugin` (`dist/claude-code/`), with `.claude-plugin/` and `skills/` at the top of the zip |
| `SHA256SUMS` | Checksums of every `motif-*` asset, now including the zip |
| `THIRD-PARTY-NOTICES.txt` | **New.** The licences of what Motif ships: axe-core (MPL-2.0, inside the tool), Motion (MIT) and the 11 bundled fonts (OFL-1.1, inside the plugin), and Bun (inside the tool) |

Changes to the workflow:

- **Versions agree.** The build fails unless the tag equals `v` + `skill/VERSION` (as today) and the built plugin's `plugin.json` has the same version.
- **Plugin job.** One job on Linux runs `bun run plugin` and zips `dist/claude-code/` with its files in a fixed order, keeping the bootstrap's executable flag where the zip format allows.
- **Publish.** `gh release create` gets `--prerelease` while the version is below 1.0, and `--notes-file docs/releases/<tag>.md` instead of `--generate-notes`. The release fails if that notes file is missing.
- **Dry run.** `workflow_dispatch` keeps building everything, the zip included, without publishing.

## 4. The marketplace

A new file, `.claude-plugin/marketplace.json` at the repository root:

```json
{
  "name": "motif",
  "description": "Motif: design guide tools for AI coding agents.",
  "owner": { "name": "7mxd", "url": "https://github.com/7mxd" },
  "plugins": [
    {
      "name": "motif",
      "description": "Design and build polished, consistent app UI from a design guide your agent follows.",
      "source": {
        "source": "archive",
        "url": "https://github.com/7mxd/motif/releases/download/v0.1.0/motif-claude-code.zip",
        "sha256": "<the zip's checksum from SHA256SUMS>"
      }
    }
  ]
}
```

- **Added after the release exists.** A script, `bun cli/scripts/marketplace.ts <tag>`, reads that release's `SHA256SUMS` and writes the file. It's committed in the follow-up step (§7), so the marketplace never points at a file that isn't there.
- **No `version` in the entry.** The version comes from the zip's own `plugin.json`, so Claude Code offers an update whenever a release raises it.
- **A test keeps it well formed:** the marketplace and entry are named `motif` (the plugin's own name), the source is an `archive` whose URL is `https://github.com/7mxd/motif/releases/download/v<semver>/motif-claude-code.zip`, and `sha256` is 64 hex characters.

People install with:

```
/plugin marketplace add 7mxd/motif
/plugin install motif@motif
```

(or `claude plugin marketplace add 7mxd/motif` and `claude plugin install motif@motif` in a shell). They need git, which Claude Code uses to add a GitHub marketplace, and Claude Code 2.1.224 or later, the first with `archive` sources. The zip downloads over HTTPS, so no GitHub account or SSH key is needed.

## 5. One change to the skill

On macOS, Linux, Git Bash and WSL, the skill runs its bootstrap as `sh "<skill folder>/bin/motif" <command>` instead of running the file directly. Claude Code unpacks the plugin from a zip, and whether the executable flag survives is outside Motif's control; the bootstrap is a POSIX shell script, so `sh` runs it either way. Windows keeps `motif.cmd`. Every place in `skill/` that shows how to run the tool says the same.

## 6. Docs

- **README** (in the follow-up commit, so it never shows commands that don't work yet):
  - "Work in progress" becomes a **Preview (v0.1.0)** note: what's in it (Claude Code; React web and plain web) and what v1 still needs (other agents, more stacks, Test A).
  - A new **Install** section: the two commands, the requirements, and what happens on first use (the tool downloads once, about 100 MB, checked against the release; screenshots and previews use the Chrome or Edge you have, or `motif browser install` downloads one, about 120 MB, after asking).
- **Plugin README** (`plugin/claude-code/README.md`): leads with the marketplace install; building from source moves under "Develop".
- **Release notes** (`docs/releases/v0.1.0.md`): what's in it, how to install, requirements, known limits (below), and what's next.
- **`THIRD-PARTY-NOTICES.txt`** at the repository root, uploaded with each release.

Known limits stated in the notes:

- Claude Code only; React web and plain web only.
- The tool binaries aren't code-signed. Downloaded by the bootstrap they run without a browser warning; downloaded by hand, macOS or Windows may warn.
- Windows on ARM runs the x64 tool.

## 7. Checks and release steps

**Before tagging:**

1. The full test suite, the typecheck, and CI on all three systems.
2. `claude plugin validate` on the built plugin.
3. A dry run of the release workflow (`workflow_dispatch`): everything builds, the zip included, nothing is published.
4. A real install of the locally built plugin through a local marketplace (a directory with a relative-path entry), in a throwaway Claude Code configuration (`CLAUDE_CONFIG_DIR` pointing at a temporary folder), with `claude plugin marketplace add`, `claude plugin install` and `claude plugin details`. Only `claude plugin` commands run; no Claude session starts, and the developer's own configuration isn't touched.

**Release steps**, each after the developer's approval:

1. **Prepare.** The workflow changes, the marketplace script, the `sh` change, the plugin README, the release notes and the notices go into `main`, with CI green.
2. **Tag `v0.1.0`** and push the tag. The workflow publishes the pre-release, then the post-release check runs on Windows, macOS and Linux:
   - download `motif-claude-code.zip` and `SHA256SUMS` from the release and check the zip;
   - unpack it, set `MOTIF_HOME` to an empty folder, leave `MOTIF_BIN` unset, and run `--version` and `doctor --json` through the plugin's bootstrap (`sh …/bin/motif`, or `motif.cmd` on Windows): the tool is downloaded from the release and checked, `--version` prints the tag's version, and `doctor --json` returns valid JSON.
3. **Follow-up commit**: `.claude-plugin/marketplace.json` (written by the script), the README's Install section and preview note. Then, on the developer's PC in a throwaway configuration: `claude plugin marketplace add 7mxd/motif`, `claude plugin install motif@motif`, `claude plugin details motif` lists Motif's five skills, and `doctor` runs through the installed plugin's bootstrap.

**If something is wrong after step 2:** with the developer's approval, delete the release and the tag, fix, and tag again. Until step 3 lands, no one can install it through Claude Code.

## 8. Out of scope

- Packages for other agents and an installer (Part 3); Anthropic's plugin directory.
- Code signing and notarization of the binaries.
- Turning on auto-update for users (each user chooses it in `/plugin`).
- Running the post-release check on ARM Windows or ARM Linux. It runs on x64 Windows, x64 Linux and Apple silicon macOS; the Linux ARM tool is still built and published.

## 9. Risks

| Risk | Answer |
|---|---|
| The executable flag is lost when Claude Code unpacks the zip | The skill runs the bootstrap with `sh` (§5); the post-release check runs it the same way |
| A user's Claude Code is older than 2.1.224 | The README and notes state the minimum version |
| No git on the user's machine | Required by Claude Code to add a GitHub marketplace; stated in the requirements |
| The marketplace points at a missing or changed zip | It's written from the published `SHA256SUMS` after the release exists, and Claude Code refuses a zip whose checksum differs |
| A broken release reaches users | The marketplace commit is the last step, after every check has passed |
