# Motif v0.6.0 (preview)

Motif works in Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI and OpenCode, for **React web** apps, **plain web** sites (HTML, CSS and JavaScript without a framework), **Flutter**, **Jetpack Compose**, **React Native with Expo** and **SwiftUI** apps, and now **Vue** (and Nuxt), **Svelte** (and SvelteKit) and **Angular** apps. Each new stack gets the whole of Motif: theme code, checks, a drafted guide from an existing app, screenshots, the audit and a stack guide for your agent ([what each stack gets](https://github.com/7mxd/motif/blob/main/docs/parity.md)). This preview also makes the screenshots and the audit more accurate on every web stack.

Motif keeps your app's design in a guide your agent follows, `DESIGN.md` and `design/tokens.json`. It shows mockups before code, screenshots your real app after, checks your code against the guide, and reviews the result in plain words.

## Install

**Claude Code**

```
/plugin marketplace add 7mxd/motif
/plugin install motif@motif
```

**Codex**

```
codex plugin marketplace add 7mxd/motif
codex plugin add motif@motif
```

**GitHub Copilot CLI**

```
copilot plugin marketplace add 7mxd/motif
copilot plugin install motif@motif
```

In VS Code, run "Chat: Install Plugin From Source" and enter `7mxd/motif`.

**Cursor:** add the plugin marketplace `7mxd/motif` in Cursor's plugin settings, or in the CLI run `cursor-agent plugin marketplace add https://github.com/7mxd/motif`.

**Gemini CLI**

```
gemini extensions install https://github.com/7mxd/motif --ref plugins --auto-update
```

**OpenCode, or any agent that reads `~/.agents/skills`**

- macOS and Linux: `curl -fsSL https://raw.githubusercontent.com/7mxd/motif/main/install.sh | sh`
- Windows PowerShell: `irm https://raw.githubusercontent.com/7mxd/motif/main/install.ps1 | iex`

The install script downloads the skill from this release, checks it against `SHA256SUMS` and puts it where OpenCode (or the shared `~/.agents/skills`) reads it. To read it first, download `install.sh` or `install.ps1` from the repository and run it from there.

Then start Motif: `/motif:design` in Claude Code, `$motif` in Codex, `/motif` everywhere else.

You need git, and Claude Code 2.1.224 or later if you use Claude Code. The first time Motif runs, it downloads its tool (about 100 MB) from this release and checks it against `SHA256SUMS`. Screenshots and previews use the Chrome or Edge you have; if you have neither, Motif asks before downloading a private browser (about 120 MB to download, about 300 MB on disk).

Motif runs on your computer. Previews and screenshots stay there, nothing is uploaded, and there's no telemetry.

Design sources are optional: `motif connect` sets one up (Motion, Refero, 21st.dev, 60fps.design) in each agent you pick, with any key typed only in your own terminal.

## What's new

The three new stacks share React web's theme, so Vue, Svelte, Angular and React apps made from the same guide look the same. On each, `motif tokens` writes its files in the app's own folders and prints the one step that wires the theme in; it never edits a file of the app's. `motif shot` starts the app's own dev script and draws its pages at the web's sizes, as on React web.

**Vue and Nuxt**

- `motif tokens` writes `motif.css` (and, with Tailwind v4, `motif.tailwind.css`) in `src/styles/`, or `assets/css/` in a Nuxt app, and `motion.ts` for Motion for Vue. The wiring note names `main.ts` (or `main.js`), or `nuxt.config.ts` in a Nuxt app. A Vue app still importing v0.5.0's `design/generated/motif.css` is told that file is no longer updated, and what to import instead.
- `motif check` reads `.vue` files: templates, `:style` bindings, `<Transition>` durations, Motion for Vue's settings and style blocks, with fixes in Vue's terms. `motif extract` drafts from the app's CSS and style blocks, with their dark values, and turns Vuetify's themes into light, dark and variants.
- `motif shot` starts the app's `dev` script (Vite, or `nuxt dev`, waiting while Nuxt shows its loading screen) and takes routes from Nuxt's `pages/`, vue-router's file routes or a router's routes. It needs Vue 3 with Vite, or Nuxt 3 or 4.

**Svelte and SvelteKit**

- `motif tokens` writes `motif.css` (and the Tailwind v4 theme) in `src/lib/styles/`, and `src/lib/design/motion.ts` in Svelte's terms: durations in milliseconds, easing functions, settings for Svelte's `Spring`, and Motion's springs for `animate()`. The wiring note imports through `$lib` (SvelteKit 2), `#lib` (SvelteKit 3) or `main.ts` (Vite).
- `motif check` reads `.svelte` files: markup and `{…}` values, `style:` and `class:` directives, transitions, animations, `Spring` and `Tween` settings and style blocks, with fixes in Svelte's terms. `motif extract` drafts from the app's CSS and style blocks, with their dark values (a shadcn-svelte `app.css`, say).
- `motif shot` starts the app's `dev` script (SvelteKit's or Vite's) and takes routes from SvelteKit's `src/routes` (groups, optional parameters, layout resets), svelte-spa-router's hash routes or svelte-routing. It needs Svelte 5, with SvelteKit 2 or 3 or with Vite. SvelteKit 3 needs Node.js 22.17 or later, which `motif doctor` checks.

**Angular**

- `motif tokens` writes React web's files, byte for byte: `motif.css` (and the Tailwind v4 theme) in `src/styles/`, and `src/app/design/motion.ts` for Motion's `animate()`. Enter and leave animations (`animate.enter`, `animate.leave`) take their timing from the CSS variables; nothing is written for the deprecated `@angular/animations`. The wiring note is one line in the styles file `angular.json` names: `@import`, Sass's `@use`, or after `@import "tailwindcss"`.
- `motif check` reads component templates, in an `.html` file or inline in `template:`, and inline `styles:`: `[style.width.px]`, `[ngStyle]`, `[ngClass]`, the classes `animate.enter` adds, and `@angular/animations` timings, with fixes in Angular's terms. `motif extract` drafts from global and component styles (CSS and Sass), Tailwind v4's `@theme`, and Angular Material's system colours and `mat.theme` font. A Material palette Motif can't read (`mat.$azure-palette`) is named in a note, to set by hand.
- `motif shot` starts the app's `start` script when it runs `ng serve` (else `dev`) on a free port, and takes routes from `provideRouter` or `RouterModule.forRoot`, lazy-loaded children included. It needs Angular 15 or later, with standalone components or NgModules. Each Angular version needs a Node.js in its own range, which `motif doctor` checks: Angular 22 needs 22.22.3 or later in Node 22, 24.15 or later in Node 24, or Node 26; Angular 20 and 21 need 20.19 or later in Node 20, 22.12 or later in Node 22, or Node 24 and later.

**Every web stack**

React web, plain web, Vue, Svelte and Angular share these.

- **Right to left at the desktop size.** Desktop right-to-left screenshots of pages that fit the screen came out shifted sideways (Chrome lays the page out 1 px wide for a full-page capture). They're now drawn where they are laid out.
- **Tap targets.** The audit compares sizes in whole pixels, as it reports them: a 43.6 px button is no longer called smaller than 44. It counts a hit area a component library puts over the centre of a control (Angular Material's, say) instead of reporting the control. And it names a control by `aria-labelledby` or an inner image's `alt`: a link named only by its logo is no longer "A link".
- **Redirects in the browser.** A page the app's router sends elsewhere (to sign-in, say) is reported as "went to /login", and its screenshots are labelled so.
- **Loading states.** The web stack guides say how to time skeletons and spinners from the motion roles, and that safe-area insets need no `motif-ok`.

**Sturdier**

- A clean audit says "no contrast or tap-target problems found". The words were garbled when the reduced-motion check didn't run.
- `motif tokens`' "Next:" wiring note is no longer hidden by a comment that mentions `motif.css`: only a real import counts as wired.

## Known limits

- Vue 2 and Nuxt 2, Svelte 4 and SvelteKit 1, and Angular 14 and older aren't supported. `motif doctor` says so. The CSS theme, `motif check` and `motif extract` still work there, and `motif shot --url` against an app you start yourself.
- Angular: when `angular.json` has several application projects, Motif reads the first and names it; name another by its folder in `design/motif.json`. An Nx workspace whose apps have no `package.json` of their own is read one app at a time, each named in `design/motif.json`. `motif shot` can't start an app without its own `package.json`: start it yourself and pass its address with `--url`.
- A redirect in a hash router (`/#/admin` to `/#/sign-in`) isn't noticed.
- `motif doctor` doesn't check that Node.js is new enough for the app's Nuxt (Nuxt 4.6 needs 22.22.3, or 24.15 or later); npm warns.
- Svelte's `Spring` follows the guide's springs at 60 frames a second. On a faster screen it is stiffer and bounces less; `motionSpring` in `motion.ts` is the same on every screen.
- `motif extract` doesn't read an UnoCSS theme. `motif check` reads a git submodule's files as the app's; leave them out with `ignore` in `design/motif.json`.
- On Svelte, as on React web, one reduced-motion check anywhere in the app counts for the whole app.
- React Native without Expo isn't fully supported: theme code, checks and drafts work, and for screenshots you run the app on react-native-web and pass its address to `motif shot --url`. Expo screenshots come from the web target, so native-only components and platform fonts can look different.
- SwiftUI screenshots need a Mac with Xcode. Motif refuses a Swift package, an app that uses CocoaPods, and a project that uses files outside its folder, each with what to do.
- Jetpack Compose: Motif names the Compose library modules an app depends on but doesn't read them yet, and Compose Multiplatform isn't supported.
- Flutter variants change colours only: a variant's other roles (type, corners) use the default's, and `motif tokens` says which.
- A few of the starting styles' fonts cover Latin letters only: Zalando Sans (Bold), TASA Orbiter (Dark Tech's headings) and Public Sans (Trust). For Cyrillic or Greek, pick a pairing from the type pairings guide that covers them.
- Cursor's plugin install is checked by hand, not by the release checks: its CLI adds the marketplace, and installing the plugin happens in Cursor. The release checks add the marketplace on Windows and Linux only, since Cursor's CLI can't keep its sign-in on CI's macOS machine.
- Codex asks multiple-choice questions only in Plan mode; elsewhere Motif asks in a numbered list.
- The tool binaries aren't code-signed. The plugin downloads and checks them, so they run without a warning; a binary you download by hand may get one from macOS or Windows.
- Windows on ARM runs the x64 tool.

## Files

| File | What it is |
|---|---|
| `motif-claude-code.zip` | The Claude Code plugin, installed through the marketplace |
| `motif-skill.zip`, `motif-skill.tar.gz` | The skill alone, which `install.ps1` and `install.sh` download |
| `motif-windows-x64.exe`, `motif-darwin-arm64`, `motif-darwin-x64`, `motif-linux-x64`, `motif-linux-arm64` | The `motif` tool, downloaded by the skill when it's first needed |
| `SHA256SUMS` | Checksums of all of the above |
| `THIRD-PARTY-NOTICES.txt` | The licences of the other works Motif ships |
