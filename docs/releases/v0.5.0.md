# Motif v0.5.0 (preview)

Motif works in Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI and OpenCode, for **React web** apps, **plain web** sites (HTML, CSS and JavaScript without a framework), and now **Flutter**, **Jetpack Compose**, **React Native with Expo** and **SwiftUI** apps. Each new stack gets the whole of Motif: theme code, checks, a drafted guide from an existing app, screenshots, the audit and a stack guide for your agent ([what each stack gets](https://github.com/7mxd/motif/blob/main/docs/parity.md)). This preview also brings design variants, your project's own fonts, and right-to-left screenshots to every stack.

Motif keeps your app's design in a guide your agent follows, `DESIGN.md` and `design/tokens.json`. It shows mockups before code, screenshots your real app after, checks your code against the guide, and reviews the result in plain words.

## Install

**Claude Code**

```
/plugin marketplace add 7mxd/motif
/plugin install motif@motif
```

**Codex**

```
codex plugin marketplace add 7mxd/motif
codex plugin add motif@motif
```

**GitHub Copilot CLI**

```
copilot plugin marketplace add 7mxd/motif
copilot plugin install motif@motif
```

In VS Code, run "Chat: Install Plugin From Source" and enter `7mxd/motif`.

**Cursor:** add the plugin marketplace `7mxd/motif` in Cursor's plugin settings, or in the CLI run `cursor-agent plugin marketplace add https://github.com/7mxd/motif`.

**Gemini CLI**

```
gemini extensions install https://github.com/7mxd/motif --ref plugins --auto-update
```

**OpenCode, or any agent that reads `~/.agents/skills`**

- macOS and Linux: `curl -fsSL https://raw.githubusercontent.com/7mxd/motif/main/install.sh | sh`
- Windows PowerShell: `irm https://raw.githubusercontent.com/7mxd/motif/main/install.ps1 | iex`

The install script downloads the skill from this release, checks it against `SHA256SUMS` and puts it where OpenCode (or the shared `~/.agents/skills`) reads it. To read it first, download `install.sh` or `install.ps1` from the repository and run it from there.

Then start Motif: `/motif:design` in Claude Code, `$motif` in Codex, `/motif` everywhere else.

You need git, and Claude Code 2.1.224 or later if you use Claude Code. The first time Motif runs, it downloads its tool (about 100 MB) from this release and checks it against `SHA256SUMS`. Screenshots and previews use the Chrome or Edge you have; if you have neither, Motif asks before downloading a private browser (about 120 MB to download, about 300 MB on disk).

Motif runs on your computer. Previews and screenshots stay there, nothing is uploaded, and there's no telemetry.

Design sources are optional: `motif connect` sets one up (Motion, Refero, 21st.dev, 60fps.design) in each agent you pick, with any key typed only in your own terminal.

## What's new

**Flutter**

- `motif tokens` writes `lib/design/motif_theme.dart`: a `ThemeExtension`, light and dark `ThemeData` with an explicit colour scheme, the text theme with the Arabic companion, sizes, motion and every variant. Several apps in a monorepo can share one theme through `themeDir`.
- `motif check` finds colours, sizes, fonts, durations, curves and springs typed in Dart, with Dart fixes. `motif extract` drafts a guide from `ThemeData`, `ColorScheme` and palette classes, with parallel palettes as variants.
- `motif shot` draws the app's routes (go_router or named routes) with `flutter test`: no device, simulator or Mac. It needs the Flutter SDK 3.27 or later. A state is a Dart script, and `design/states/setup.dart` and `http.json` reach screens behind sign-in or live data without leaving your computer.

**Jetpack Compose**

- `motif tokens` writes `MotifTheme.kt` in the app module's package: colour roles light and dark, every variant, the Material colour scheme and type with the Arabic companion, and fonts in `res/font`. It never edits your Gradle files.
- `motif check` reads Kotlin, and `motif extract` drafts from the template's `Color.kt` and `Theme.kt` and your colour constants, with parallel schemes as variants.
- `motif shot` draws Navigation Compose routes and `@Preview` functions on the JVM with Robolectric: no phone or emulator. It needs JDK 17, the Android SDK and the app's Gradle wrapper, and an app on Kotlin 2.0, a Compose BOM of 2025.08.00 or later and the Android Gradle Plugin 8.6 or later. The first run downloads about 1.5 GB; later runs work offline.

**React Native with Expo**

- `motif tokens` writes `src/design/motif-theme.tsx` with `MotifProvider`, `useMotifTheme()`, every variant light and dark, and the fonts for `expo-font`.
- `motif check` reads your styles, and `motif extract` drafts from colour objects (the starter's `Colors`, say), styles and the fonts the app loads, including `@expo-google-fonts` packages and a `useFonts` map defined in another file.
- `motif shot` draws Expo's web target in Chrome and starts Expo's web server itself. It needs Expo SDK 52 or later and the app's web packages (`motif doctor` checks them). It takes Expo Router routes or React Navigation's linking config.

**SwiftUI**

- `motif tokens` writes `Design/MotifTheme.swift` in the app target's folder, with `.motifTheme()`, every variant light and dark, type that scales with Dynamic Type, springs, and the fonts in `Fonts/`.
- `motif check` reads Swift, and `motif extract` drafts from asset catalogue colour sets (light and dark), `Color` constants and size constants, with parallel sets as variants. Both work on any computer.
- `motif shot` builds a copy of the app with a test of its own and draws the root view and `#Preview`s in a simulator it creates and deletes, or on the Mac for a Mac app. It needs a Mac with Xcode 16 or later, and an app targeting iOS 17 or macOS 14 or later. It never builds inside your project or edits the Xcode project.

**Every stack**

- **Design variants.** A guide can carry several palettes (one per brand, say, or a high-contrast look). `motif validate` checks readability in each, `motif tokens` writes every variant, and `--variant <id>` (or `all`) shows one in mockups and screenshots. `motif extract` turns parallel palettes into variants.
- **Your project's own fonts.** A guide can name font files the app ships. They're used in mockups and theme code and never fetched from the web.
- **Right to left.** `motif shot --rtl` also screenshots every screen right to left, in Arabic unless you name another language.
- **The audit** now finds controls with no accessible name, beside contrast, tap targets and reduced motion.
- A type stack that starts with the system font (`system-ui, Readex Pro`) keeps its Arabic companion on every stack.
- **A light action colour stays readable as text.** When the guide's action colour is too light to read on the page (a mint or a yellow, say), theme code adds `actionText`: the same hue, made darker (or lighter, on a dark page) until it reads. Flutter's text and outlined buttons use it, Compose's Material `primary` is it (the brand colour stays the fill), and SwiftUI tints with it.
- **Drafted guides validate as drafted:** drafted text colours always read on the drafted backgrounds, in light and dark. A see-through border or text colour (a hairline at 8%) is drafted as it shows over the background, not as its solid colour. A font the app ships is drafted as its own, not as a Google font. The smallest type roles are the small sizes the app uses most.
- Dark screenshots that look the same as light, and a variant that looks the same as the default, are noticed even when a spinner differs. A variant that only adds a new colour still counts as a change.
- `--variant all` on a guide with one palette draws it once and says so, instead of refusing.

**Sturdier**

- Several first runs at once (an agent starting Motif in parallel) no longer fail on Windows with "Permission denied": a run never replaces a tool another run already put in place.

## Known limits

- Vue, Svelte and Angular come next. Motif detects them and helps with general guidance, and `motif tokens` writes plain CSS variables there.
- React Native without Expo isn't fully supported: theme code, checks and drafts work, and for screenshots you run the app on react-native-web and pass its address to `motif shot --url`. Expo screenshots come from the web target, so native-only components and platform fonts can look different.
- SwiftUI screenshots need a Mac with Xcode. Motif refuses a Swift package, an app that uses CocoaPods, and a project that uses files outside its folder, each with what to do.
- Jetpack Compose: Motif names the Compose library modules an app depends on but doesn't read them yet, and Compose Multiplatform isn't supported.
- Flutter variants change colours only: a variant's other roles (type, corners) use the default's, and `motif tokens` says which.
- A few of the starting styles' fonts cover Latin letters only: Zalando Sans (Bold), TASA Orbiter (Dark Tech's headings) and Public Sans (Trust). For Cyrillic or Greek, pick a pairing from the type pairings guide that covers them.
- Cursor's plugin install is checked by hand, not by the release checks: its CLI adds the marketplace, and installing the plugin happens in Cursor. The release checks add the marketplace on Windows and Linux only, since Cursor's CLI can't keep its sign-in on CI's macOS machine.
- Codex asks multiple-choice questions only in Plan mode; elsewhere Motif asks in a numbered list.
- The tool binaries aren't code-signed. The plugin downloads and checks them, so they run without a warning; a binary you download by hand may get one from macOS or Windows.
- Windows on ARM runs the x64 tool.

## Files

| File | What it is |
|---|---|
| `motif-claude-code.zip` | The Claude Code plugin, installed through the marketplace |
| `motif-skill.zip`, `motif-skill.tar.gz` | The skill alone, which `install.ps1` and `install.sh` download |
| `motif-windows-x64.exe`, `motif-darwin-arm64`, `motif-darwin-x64`, `motif-linux-x64`, `motif-linux-arm64` | The `motif` tool, downloaded by the skill when it's first needed |
| `SHA256SUMS` | Checksums of all of the above |
| `THIRD-PARTY-NOTICES.txt` | The licences of the other works Motif ships |
