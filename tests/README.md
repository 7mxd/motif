# Tests

Fixtures and evaluations for Motif. Nothing here ships to users: skill installs copy only `skill/`, and releases contain only the tool's binaries. `node_modules/`, `.next/` and eval results are never committed. The tool's own unit tests live in `cli/test/`.

## Fixtures

- **`fixtures/react-contract-app/`** — Larder, a grocery-ordering app: Next.js 16 and Tailwind v4, a design guide from the Warm starting style, the React web guide's 20 starter components, an app shell and three screens (Home, Products, a product). It is clean by construction: CI checks it with `motif validate` and `motif check` (`cli/test/fixtures-contract.test.ts`), and its build and `motif shot --audit` were checked when it was made. Test B adds features to copies of it.
- **`fixtures/react-seeded-app/`** — the same app with 23 planted problems: `overlay/` holds the files that differ, and `seeded-issues.json` is the exact list of problems and where each one is. Test C reviews a copy and is graded against the list. Its [README](fixtures/react-seeded-app/README.md) describes every problem.
- **`fixtures/plain-contract-site/`** — Kitepost, a one-page postcard tool in plain HTML, CSS and JavaScript (no framework, no build): a design guide from the Soft starting style, its own variables defined from roles, the plain web guide's components it uses, and three state scripts (`design/states/`) for the screens behind its form. CI checks it with `motif validate`, `motif check` and, where a browser is found, `motif shot --audit` in every state (`cli/test/fixtures-plain-contract.test.ts`). Test B's `b-plain` adds a page to a copy.
- **`fixtures/plain-seeded-site/`** — the same site with 18 planted problems, listed in its `seeded-issues.json`, and without the state scripts (a review writes its own). Test C's `c-plain` reviews a copy. Its [README](fixtures/plain-seeded-site/README.md) describes every problem.
- **`fixtures/flutter-contract-app/`** — Maktaba, a neighbourhood library app in Flutter (Material 3, go_router, Riverpod, `shared_preferences`, an HTTP catalogue client), in English and Arabic: a design guide from the Minimal starting style with a Kids' corner variant (colours only) and Readex Pro for Arabic, the generated theme (`lib/design/motif_theme.dart`), and four screens plus a book's page (`/`, `/books`, `/books/:id`, `/loans`, `/sign-in`). `design/states/setup.dart` signs screenshots in, and `design/states/http.json` answers the catalogue from `design/fixtures/`. CI checks it with `motif validate`, `motif check` and `motif tokens`, and where Flutter is installed with `flutter analyze` and `motif shot --audit` in both variants, light and dark, left to right and right to left (`cli/test/fixtures-flutter.test.ts`). Test B's Flutter cases add features to copies of it.
- **`fixtures/flutter-seeded-app/`** — Maktaba with 16 planted problems (10 exact, 6 that need judgement), listed in its `seeded-issues.json`. Test C's Flutter case reviews a copy. Its [README](fixtures/flutter-seeded-app/README.md) describes every problem.
- **`fixtures/compose-contract-app/`** — Rafiq, a habit tracker in Jetpack Compose (Material 3, Navigation Compose with string routes, a ViewModel per screen over an in-memory repository, `SharedPreferences` for the signed-in flag), in English and Arabic, shaped as Android Studio makes a project (one `app` module, a version catalogue and the Gradle wrapper): a design guide from the Soft starting style with a High contrast variant (colours only) and Readex Pro for Arabic, the generated theme (`app/src/main/java/dev/motif/rafiq/ui/motif/MotifTheme.kt`), a preview for each screen, and Today (`/`), a habit's page (`/habit/{id}`), Add a habit (`/add`) and Sign in (`/sign-in`). `design/states/Setup.kt` signs screenshots in and starts each from the same habits. CI checks it with `motif validate`, `motif check` and `motif tokens`, and where a JDK and the Android SDK are found with Gradle's compiler and `motif shot --audit` in both variants, light and dark, left to right and right to left (`cli/test/fixtures-compose.test.ts`).
- **`fixtures/compose-seeded-app/`** — Rafiq with 15 planted problems (10 exact, 5 that need judgement), listed in its `seeded-issues.json`. Its [README](fixtures/compose-seeded-app/README.md) describes every problem.
- **`fixtures/rn-contract-app/`** — Dukkan, a corner shop's ordering app in React Native with Expo (SDK 58, Expo Router, in-memory data), in English and Arabic: a design guide from the Minimal starting style with a Night market variant (colours only) and Readex Pro for Arabic, the generated theme (`design/motif-theme.tsx`), the components the React Native guide's starter set needs, and three screens plus a product's page (`/`, `/basket`, `/sign-in`, `/products/[id]`). It has no orders or favourites screen: test B's Expo cases add them. `package.json` and `package-lock.json` are committed, never `node_modules/`. CI checks it with `motif validate` and `motif check`, and where Node and npm are found it installs a copy and checks it with `motif tokens`, `motif check`, `npx tsc --noEmit` and, with a browser, `motif shot --audit` through Expo's web target in both variants, light and dark, left to right and right to left (`cli/test/fixtures-rn.test.ts`).
- **`fixtures/rn-seeded-app/`** — Dukkan with 14 planted problems (10 exact, 4 that need judgement), listed in its `seeded-issues.json`. Test C's Expo case reviews a copy. Its [README](fixtures/rn-seeded-app/README.md) describes every problem.
- **`fixtures/swiftui-contract-app/`** — Qahwa, a coffee shop's loyalty app in SwiftUI for iOS 17, in English and Arabic, shaped as Xcode 16's App template makes a project (object version 77, the app's folder a synchronized group, Swift 5): a design guide from the Warm starting style with an Evening variant (colours only), the system's serif and sans-serif with Readex Pro for Arabic (bundled in `Qahwa/Fonts/` with its licence, registered by `UIAppFonts`), the generated theme (`Qahwa/Design/MotifTheme.swift`), the root (the menu) and a `#Preview` each for the menu, a drink's page, the loyalty card and sign-in. It has no orders or rewards-history screen: test B's SwiftUI cases add them. `design/states/Setup.swift` signs screenshots in. CI checks it with `motif validate`, `motif check` and `motif tokens`, and on a Mac with Xcode with `xcodebuild` and `motif shot --audit` in both variants, light and dark, left to right and right to left (`cli/test/fixtures-swiftui.test.ts`).
- **`fixtures/swiftui-seeded-app/`** — Qahwa with 16 planted problems (11 exact, 5 that need judgement), listed in its `seeded-issues.json`. Test C's SwiftUI case reviews a copy. Its [README](fixtures/swiftui-seeded-app/README.md) describes every problem.
- **`fixtures/briefs/`** — six briefs for test D's new apps: three web apps (Stride, Ledgerly, Bloom), Sahm, a Flutter app, Nabta, a Jetpack Compose app, and Rihla, an Expo app, the last three in English and Arabic.
- **`fixtures/assemble.ts`** — builds a working copy of any of these fixtures in an empty folder:

  ```bash
  bun tests/fixtures/assemble.ts react-contract-app <empty folder>
  bun tests/fixtures/assemble.ts react-seeded-app <empty folder>
  bun tests/fixtures/assemble.ts plain-contract-site <empty folder>
  bun tests/fixtures/assemble.ts plain-seeded-site <empty folder>
  bun tests/fixtures/assemble.ts flutter-contract-app <empty folder>
  bun tests/fixtures/assemble.ts flutter-seeded-app <empty folder>
  bun tests/fixtures/assemble.ts compose-contract-app <empty folder>
  bun tests/fixtures/assemble.ts compose-seeded-app <empty folder>
  bun tests/fixtures/assemble.ts rn-contract-app <empty folder>
  bun tests/fixtures/assemble.ts rn-seeded-app <empty folder>
  bun tests/fixtures/assemble.ts swiftui-contract-app <empty folder>
  bun tests/fixtures/assemble.ts swiftui-seeded-app <empty folder>
  ```

  Then run `npm install` in a React app's folder to build or run it (`npm ci` in an Expo app's, then `npx expo start --web`), or `flutter pub get` in a Flutter app's; a Compose app builds with its own Gradle wrapper (`./gradlew :app:compileDebugKotlin`, with a JDK and the Android SDK), a SwiftUI app with Xcode on a Mac (`xcodebuild -scheme Qahwa -destination "generic/platform=iOS Simulator" build`), and a plain site needs nothing installed.

## Evals

`evals/` runs tests B, C and D from the design spec through your signed-in Claude Code, never an API key, one case at a time and only when you start it: `bun tests/evals/run.ts --list` to see the cases. [evals/README.md](evals/README.md) explains what each session gets, how to resume after a usage limit, and how cases are graded.
